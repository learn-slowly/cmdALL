# A. 못 여는 파일 — 애플 미리보기로 받기 (설계)

- 날짜: 2026-07-25
- 상태: 설계 승인 대기
- 상위 문서: `2026-07-25-finder-preview-direction.md`(조각 A~E 중 **A**, 순서 ①안의 첫 조각)
- 사용자 결정: ① 앱 안에서 보이기 + 원래 앱 버튼 ② 스페이스바 빠른 보기도 **이번에 같이**

---

## 1. 목적

지금 cmdALL은 아는 형식(글·PDF·사진·한글/오피스·음악·영상) 밖의 파일을 **전부 마크다운으로 연다**(`Sources/Models/DocumentKind.swift:80`). 그래서 `발표자료.pptx`를 누르면 깨진 글자가 화면 가득 뜬다. 파인더 대신 쓰기 시작하면 아무거나 누르게 되므로 매일 부딪힌다.

애플이 만들어 둔 미리보기(QuickLook)를 앱 안에 빌려와 이 자리를 메운다. **우리가 형식을 직접 뜯어 읽지 않는다.**

## 2. 실측으로 확인한 것 (추측 아님)

두 가지를 이 맥에서 직접 재고 시작한다.

**(a) 맥에게 "이거 글자 파일이냐"고 물으면 정확히 갈라준다** — `UTType.conforms(to: .text)`

| 글자 파일이라고 답함 | 아니라고 답함 |
|---|---|
| `csv` `json` `swift` `log` `yml` `xml` `html` `py` `sh` `rtf` `md` `txt` | `pptx` `ppt` `key` `numbers` `pages` `zip` `psd` `ai` `epub` `ttf` `dmg` `app` |

**(b) 미리보기 부품이 이 프로젝트 설정에서 쓰인다** — `QLPreviewView`가 macOS 14 대상으로 타입 검사 통과(`import Quartz`).

**(c) 세션에는 파일 경로만 저장되고 종류는 열 때 다시 판정한다**(`AppState.restoreSessionIfNeeded` → `loadDocument(at:)`). 따라서 **옛 탭 이전 작업이 필요 없고**, 껐다 켜면 새 규칙이 자동 적용된다.

### 실측이 드러낸 함정 두 개

1. **맥이 모르는 확장자는 "글자 아님"으로 답한다.** `.conf` → `dyn.ah62d4rv4ge80g55sq2`, `.mdx` → `dyn.…`. 실제론 글자 파일인데 미리보기로 잘못 간다.
2. **`.rtf`는 "글자"라고 답하지만** 편집기로 열면 서식 부호가 그대로 보인다.

→ 1은 **"글로 열기" 탈출구**로, 2는 **예외 목록**으로 막는다(§3).

## 3. 갈림길 규칙

파일을 열 때 **이 순서로** 판정한다. 순서가 안전장치다 — 아는 것을 먼저 확정해야 새 갈래로 새지 않는다.

```
1. 사진·PDF·한글/오피스·음악/영상 확장자인가?  → 지금 그대로 (손대지 않음)
2. rtf 인가?                                → 미리보기   (예외 목록)
3. 맥이 "글자 파일"이라 답하는가?              → 글로 열기 (지금 그대로)
4. 그 밖 전부                                → 미리보기   (새로 만드는 갈래)
```

- 1단계가 기존 `DocumentKind.init(from:)`의 앞부분 그대로다. **아는 여섯 종류의 동작은 한 줄도 바뀌지 않는다.**
- 4단계를 위해 `DocumentKind`에 갈래 하나(`quickLook`)를 더한다.
- 확장자가 없는 파일(`README` 등)은 4단계로 간다. 애플 미리보기가 글자로 보여주므로 읽는 데 지장 없고, 고치려면 "글로 열기"를 누른다.

## 4. 화면 — 탭으로 여는 미리보기

```
┌──────────────────────────────────────────────┐
│ 발표자료.pptx    [파워포인트로 열기] [글로 열기] │
├──────────────────────────────────────────────┤
│                                              │
│        애플 미리보기 화면                       │
│        (슬라이드가 그대로 보이고 넘어감)          │
│                                              │
└──────────────────────────────────────────────┘
```

- **"파워포인트로 열기"** — 그 파일의 기본 앱을 맥에 물어 **이름을 그대로 쓴다**(한컴이면 "한컴오피스로 열기"). 기본 앱이 없으면 버튼을 숨긴다.
- **"글로 열기"** — 그 탭을 편집기로 바꾼다. **그 탭이 살아 있는 동안만** 유지되고, 닫았다 다시 열면 미리보기로 돌아온다. (확장자를 기억하는 설정은 후속 후보 §9.)
- 미리보기가 아예 안 되는 파일이면 안내 문구와 위 두 버튼만 남는다. **크래시 없이** 넘어간다(기존 오피스 리더의 실패 처리와 같은 태도).

## 5. 화면 — 스페이스바 빠른 보기

- **어디서** — 라이브러리(격자·목록)와 왼쪽 트리에서 파일을 고른 상태.
- **동작** — 스페이스 → 큰 미리보기가 화면 위에 뜸 → 스페이스나 `esc` → 닫힘. **탭을 만들지 않는다.**
- **여러 개 골랐으면** — `←` `→`로 고른 것들 사이를 넘긴다.
- **아는 형식도 보여준다** — 사진·PDF·한글 문서도 스페이스로 훑을 수 있다(탭 여는 동작은 그대로).

### 반드시 지킬 것 — 키 강탈 금지

이 프로젝트에서 **같은 결함이 세 번 반복됐다**: F1b의 `⌘C`가 미리보기 글자 대신 파일을 복사, F3의 `⌘↑`가 검색창 커서를 강탈, 이미지 뷰어의 `⌘←`가 창 전체를 가로챔. 스페이스바는 **글자 입력 중에 가장 자주 눌리는 키**라 위험이 가장 크다.

- 기존 `AppState.responderYieldsFileKeys` 가드를 **그대로 재사용**한다. 글자 입력칸·미리보기(WKWebView)·PDF 화면이 활성일 때는 스페이스를 건드리지 않는다.
- 전역 단축키로 등록하지 않는다(F1b에서 확립된 규칙).
- 검사로 고정한다 — 입력칸이 활성일 때 스페이스가 미리보기를 **열지 않는지** 확인하는 자동 검사를 넣는다.

〔실기 확인 필요〕 미리보기가 떠 있는 동안 스페이스를 **미리보기 부품이 먼저 먹을 수** 있다. 닫기가 듣는지는 실제로 눌러 봐야 안다.

## 6. 만드는 것 / 손대는 곳

**새 파일 (기존 코드에 섞지 않는다 — 이 프로젝트 관례)**

| 파일 | 역할 |
|---|---|
| `QuickLookPreviewView.swift` | 애플 미리보기 부품을 SwiftUI에 얹는 껍데기 + 위쪽 버튼 줄 |
| `QuickLookRouting.swift` | §3 갈림길 규칙(순수 판정 — 파일을 읽지 않고 이름만 본다) |
| `QuickLookPanel.swift` | 스페이스바 빠른 보기 화면 |

**손대는 곳 (최소)**

- `DocumentKind` — 갈래 `quickLook` 추가, `init(from:)`에 §3 순서 반영, 정렬 순위는 **맨 끝**(음악·영상 다음)
- `AppState` — 여는 갈래 하나 추가, 스페이스 키 처리(기존 키 가드 재사용), 빠른 보기 상태
- 리더 화면 — `quickLook` 탭이면 새 화면 표시

**안 건드리는 것**: 아는 여섯 종류의 읽기·편집·저장, 검색, Claude, 폴더 정리, 위키, 파일 작업, 드래그.

## 7. 경계

- **읽기 전용.** 미리보기로는 고칠 수 없다. 원본은 열어도 바뀌지 않는다.
- **검색 대상 아님.** 색인은 `ContentExtractor`가 자기 목록(`md`·`markdown`·`txt` + PDF + 한글/오피스)으로만 본문을 뽑는다(확인함). 이 갈래는 지금도 안 들어가고, 그대로 둔다. 파일 **이름** 검색으로는 계속 잡힌다.
- **짝꿍 노트 없음.** 그건 음악·영상만의 규칙이다.
- **새 부품 안 들여옴.** `Quartz`(QuickLook)는 맥에 기본 내장. 패키지 의존성 **0**.

## 8. 위험과 막는 법

| 위험 | 막는 법 |
|---|---|
| 지금 잘 열리던 파일이 미리보기로 새어 나감 | §3 판정 **순서**를 코드로 고정 + 여섯 종류가 `quickLook`으로 가지 않는지 확인하는 자동 검사 |
| 스페이스가 글자 입력을 강탈 | 기존 키 가드 재사용 + 입력칸 활성 시 무동작 검사(§5) |
| 편집 중이던 `.conf` 같은 파일이 미리보기로 바뀜 | "글로 열기" 버튼이 탈출구. 저장 안 한 초안은 따로 보관되므로 사라지지 않음 〔실기 확인〕 |
| 미리보기가 못 여는 파일에서 앱이 멎음 | 실패해도 안내만 띄우고 넘어감(기존 오피스 리더와 같은 태도) |

## 9. 확인 방법

**자동 검사** (기존 803개에 더한다)

- 확장자별 갈래 판정 — 위 실측 표 전부 + `rtf` 예외 + 확장자 없음 + 맥이 모르는 확장자
- 아는 여섯 종류가 `quickLook`으로 가지 않음(새어 나감 방지)
- 입력칸 활성 시 스페이스 무동작

**실기 확인** (자동으로는 원리상 불가한 것 — 이 프로젝트에서 결함이 늘 여기서 나왔다)

1. `.pptx` 열어 슬라이드 넘김 / `.key` `.zip` `.psd` 열어봄
2. "파워포인트로 열기" 버튼이 실제 그 앱을 띄움
3. `.conf` 열어 "글로 열기"로 편집기 전환
4. 라이브러리에서 스페이스 → 열림, 다시 스페이스/`esc` → 닫힘
5. 여러 개 골라 `←` `→`로 넘김
6. **검색창에 글자 치는 중 스페이스** → 띄어쓰기가 되고 미리보기가 뜨지 않음
7. 기존 여섯 종류가 그대로 열림(회귀 확인)

## 10. 알려진 엣지·후속 후보

- "글로 열기"가 탭 한정이라 같은 확장자를 자주 열면 매번 눌러야 한다 → **설정에 "항상 글로 열 확장자" 목록**(후속)
- 애플 미리보기가 어느 형식까지 실제로 보여주는지는 형식마다 다르다(`zip`은 목록만 보이거나 안 보일 수 있음) → 실기에서 확인해 이 문서에 적는다
- 스페이스바 빠른 보기에서 파일을 지우거나 옮기는 동작은 넣지 않는다(1차 범위 밖)
- **이번 작업 중 발견한 별건**(고치지 않음, 보고만): 검색 색인이 `md`·`txt`·PDF·한글/오피스만 본문을 읽어서 `json`·`swift`·`csv` 같은 **글자 파일도 내용 검색에 안 잡힌다**. A와 무관한 기존 공백이라 손대지 않는다
