# 방향 정리 — "빠른 파인더 + 미리보기 앱"

- 날짜: 2026-07-25
- 상태: **순서 미정.** 조각(A~E)과 범위는 아래대로 합의, 진행 순서만 사용자 결정 대기.
- 성격: 비개발자(레고)가 읽는 방향 메모. 각 조각은 이 프로젝트 관례대로 **따로 spec → plan → 구현** 사이클을 돈다.
- 앞선 문서: `2026-07-03-finder-replacement-roadmap.md`(F1a·F1b·F3·F2 완료, **F4 미착수**)

---

## 0. 무엇을 만들려는가

지금까지 cmdALL은 "문서를 읽고 AI에게 묻는 도구"로 자랐다. 여기서 방향을 하나 더 얹는다 — **평소에 파인더를 열 일이 없는, 빠른 파일 앱이자 미리보기 앱.**

사용자가 밝힌 "지금도 파인더를 열게 되는 순간"(2026-07-25):

1. 파일 옮기고 정리할 때
2. 앱이 못 여는 파일을 만났을 때
3. 다운로드·데스크탑 같은 특정 위치로 갈 때

고르지 **않은** 것: "파일 빨리 훑어볼 때". 훑어보기는 이미 이 앱에서 하고 있다는 뜻으로 읽는다.

속도에 대해서는 **"딱히 느낀 적 없다 + 폴더 오가다닐 때"** 라고 답했다. 즉 전반은 괜찮고, 폴더를 옮겨 다닐 때만 가끔 멈칫한다.

## 1. 현재 빈틈 (코드로 확인한 것만)

| # | 빈틈 | 확인 근거 |
|---|---|---|
| 1 | **모르는 파일을 전부 마크다운으로 연다** — ppt·zip·psd·key 등을 누르면 깨진 글자가 뜬다 | `Sources/Models/DocumentKind.swift:80` — 아는 확장자가 아니면 `.markdown`으로 폴백 |
| 2 | **애플 미리보기를 쓰지 않는다** — 앱이 쓰는 QuickLook은 목록의 작은 그림(썸네일)뿐 | `Sources/Services/ThumbnailService.swift` 만 `QuickLookThumbnailing` 사용. 미리보기 화면(`QLPreviewView`)은 어디에도 없음 |
| 3 | **스페이스바 미리보기가 없다** — 훑어보려면 반드시 탭이 하나 생긴다 | 위와 같음(미리보기 화면 부재) |
| 4 | **두 폴더를 나란히 볼 수 없다** | 로드맵 F4 미착수. 또한 앱이 **창을 하나만 띄우는 구조**라 "창 두 개"로는 우회 불가 |
| 5 | **기본 위치(홈·데스크탑·다운로드·문서)가 사이드바에 없다** — 손으로 즐겨찾기에 등록해야 나타난다 | `Sources` 전체에 `downloadsDirectory`·`desktopDirectory`·`documentsDirectory` 사용처 없음 |
| 6 | **"기본 앱으로 열기"가 없다** — 우리가 못 여는 파일을 원래 앱으로 넘길 길이 없다 | "파인더에서 보기"(`NSWorkspace.selectFile`)는 사이드바·탭바에 있으나, 파일을 기본 앱으로 여는 진입점은 없음 |

## 2. 다섯 조각

### A. 못 여는 파일 〔중간〕

- **지금** — `발표자료.pptx`를 누르면 깨진 글자가 화면 가득 뜬다. `.zip`·`.psd`·`.key`도 같다.
- **바뀐 뒤** — 누르면 애플의 미리보기 화면이 앱 안에 그대로 뜬다(파인더에서 스페이스바 눌렀을 때 나오는 그 화면). 슬라이드도 넘겨 보인다. 그걸로 부족하면 위쪽 **"파워포인트로 열기"** 버튼으로 넘긴다.
- **덤** — 목록에서 파일 고르고 **스페이스바**를 누르면 탭을 만들지 않고 크게 훑어보고, 한 번 더 누르면 닫힌다. 미리보기 화면을 들이는 김에 거의 공짜로 따라온다.
- **성격** — 애플이 만들어 둔 것을 빌려 쓰는 일이라, 새로 만드는 위험이 적다. 우리가 이미 잘 여는 형식(글·PDF·사진·한글/오피스·음악·영상)은 **건드리지 않는다.**
- 〔확인 필요〕 애플 미리보기가 실제로 어느 형식까지 보여주는지는 이 맥에서 재봐야 한다(zip은 목록만 보이거나 아예 안 보일 수 있다).

### B. 보내기 〔작음〕

- **지금** — 다른 폴더로 옮기려면 오른쪽 버튼 → "폴더로 이동" → 폴더 고르는 창이 뜨고 → 클릭으로 찾아 들어가야 한다.
- **바뀐 뒤** — 파일 고르고 단축키 한 번 → 자주 쓰는 폴더 목록이 바로 뜨고 → 하나 골라 끝. 목록에 없으면 지금처럼 창을 열 수 있다.
- **성격** — 실제 옮기는 일은 이미 만들어 둔 것(배치 이동·기록·되돌리기)을 그대로 쓴다. 새로 만드는 건 "목적지 고르는 목록"뿐.
- 〔결정 필요, B 스펙에서〕 그 목록을 무엇으로 채울지 — 즐겨찾기를 그대로 쓸지, 최근 보낸 곳을 기억할지, 따로 등록할지.

### C. 두 폴더 나란히 〔큼〕

- **지금** — 한 번에 한 폴더만 본다. 다운로드에서 골라 프로젝트 폴더로 옮기려면 왔다 갔다 해야 한다.
- **바뀐 뒤** — 화면을 좌우로 갈라 왼쪽에 다운로드, 오른쪽에 목적지를 놓고, 골라서 가운데 화살표나 끌어놓기로 넘긴다.
- **성격** — 로드맵 F4. 화면 구조를 바꾸는 공사라 다섯 중 가장 크고, 기존 기능이 흔들릴 위험도 가장 크다. "지금 보는 폴더가 하나"라는 전제로 만들어진 곳들을 모두 손봐야 한다.

### D. 기본 위치 〔아주 작음〕

- **지금** — 왼쪽 목록에 홈·데스크탑·다운로드·문서가 없다.
- **바뀐 뒤** — 파인더처럼 처음부터 늘 거기 있다. 기존 즐겨찾기는 그대로 둔다.

### E. 폴더 오갈 때 매끄럽게 〔작음~중간〕

- **지금** — 폴더를 옮겨 다닐 때 가끔 멈칫한다(사용자 보고). **원인은 아직 안 재봤다.**
- **바뀐 뒤** — 먼저 어디서 걸리는지 재고, 걸리는 곳만 고친다.
- **성격** — 앞 조각들이 끝난 뒤에 재는 게 맞다. 재봤는데 별것 아니면 **안 한다.** 지금 짐작만으로 손대지 않는다.

## 3. 순서 후보 (미정)

| 안 | 순서 | 근거 |
|---|---|---|
| **①** | A → D+B → C → E | 매일 부딪히는 마찰(못 여는 파일)을 먼저 없앤다. A는 빌려 쓰는 일이라 위험이 낮으면서 "미리보기 앱" 목표의 절반을 채운다. 큰 공사(C)는 뒤로 |
| **②** | D+B → A → C → E | 작은 것부터. 빨리 눈에 보이지만, 가장 자주 겪는 불편이 뒤로 밀린다 |
| **③** | C → A → D+B → E | 가장 크게 고른 "정리"를 먼저. 다만 앞에 작은 성공 없이 가장 위험한 공사를 먼저 치는 셈 |

## 4. 이번에 하지 않을 것

- 파일 **영구 삭제** — 휴지통 이동까지만(기존 정책 유지)
- 외장하드·네트워크 드라이브 관리
- 파인더를 **시스템 전체에서** 대체하기(기본 파일 관리자 교체 등)
- ppt·psd 같은 형식을 **우리가 직접 뜯어 읽기** — 애플 미리보기에 맡긴다
- A~E 밖의 다른 개선(눈에 띄면 목록으로만 보고)

## 부록. GSG HWP(윈도우) 적용 검토 — **적용 불가**

- 대상: https://github.com/innae1121-bit/gsghwp (MIT, Python/C++/PowerShell)
- 사용자 문의(2026-07-25): "윈도우 버전인데 적용 가능한가"
- **결론: 불가.** 아래 세 가지가 각각 단독으로도 결정적이다.

1. **HWP 파일을 읽는 도구가 아니다.** 윈도우에서 **이미 켜져 있는 한/글 프로그램을 원격 조종**한다. 파일을 뜯어보는 게 아니라 "한글아, 이 표 3행을 채워"라고 시키는 방식이라, 한/글이 없으면 아무것도 못 한다.
2. **조종 방법이 통째로 윈도우 전용이다.** 한/글 프로그램 안에 자기 부품을 밀어 넣고 윈도우에만 있는 연결 통로로 말을 건다. 맥에는 그 통로도, 그 부품 형식도 없다. 코드가 공개돼 있어도 **옮기는 게 아니라 새로 만들어야 하는데, 맥엔 만들 자리가 없다.**
3. **맥 한컴은 조종을 받지 않는다(이 맥에서 실측).** `/Applications/Hancom Office HWP.app`에 자동화 창구가 없다 — `NSAppleScriptEnabled` 키 없음, 스크립트 사전(`.sdef`) 없음. 발상만 빌려 맥에서 다시 만드는 길도 막혀 있다.

**쓸 수 있는 경우**: 윈도우 PC나 가상머신을 쓴다면 그 윈도우 안에서 Claude Code와 함께. cmdALL 안에서는 아니다. (MIT이나 README에 "한컴 자동화의 **상업적** 이용은 한글과컴퓨터 별도 승인 필요"라고 명시 — 개인 용도는 무관.)

**우리 쪽 대안은 이미 있다**: kordoc은 한/글 프로그램 없이 파일을 직접 읽고, 서식 그대로 텍스트만 바꿔 저장하고(`patch`), 양식 빈칸도 채운다(`fill`). GSG HWP가 노리는 일의 상당 부분을 한/글 없이 한다. 차이는 정확도와 폭 — GSG는 진짜 한/글이 하는 일이라 표 병합·이미지 넣기·스타일까지 되지만, 그 정확도는 **윈도우 + 한/글 설치**를 대가로 치른 것이다. 맥 전용 앱이 따라갈 수 있는 길이 아니다.
