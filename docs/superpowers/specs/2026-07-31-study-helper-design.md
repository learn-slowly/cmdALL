## 쉬운 말 요약 (레고용)

**무엇을 만드나.** 지금 앱은 문서를 보고, 찾고, 물어보는 것까지 된다. 여기에 **공부를 도와주는 칸**을 하나 더 붙인다. 교재(PDF·한글·워드·사진 뭐든)를 열어놓고 버튼을 누르면 ①한 장짜리 정리 카드를 만들어 주고 ②그 내용으로 문제를 뽑아 주고 ③며칠 뒤에 "이거 다시 볼 때 됐어요"라고 챙겨 주고 ④같이 읽으면서 물어봐 주는 대화 상대가 되어 준다.

**만드는 순서(레고 확정).**
- **0단계(반나절) — 건너뛰지 않는다.** 지금 있는 AI 칸에 "정리 카드 만들기"·"문제 뽑기" 버튼 두 개만 붙여 본다. 실제 교재로 세 번 써 보고 "쓸 만하다"가 나와야 다음으로 간다.
- **1단계**: 정리 카드 + 문제 뽑기를 제대로.
- **그다음은 대화하며 공부하기(원래 3단계로 적어 둔 것)를 먼저 만든다.** 복습 챙기기(2단계)는 그 뒤에 만든다. 두 가지는 서로 기다릴 필요가 없어서 순서를 이렇게 골라도 된다.

**중요한 약속 세 가지.**
1. **교재 원본은 절대 안 건드린다.** 만들어진 카드·문제는 전부 **새 메모 파일**로만 생긴다.
2. **저장 전에 항상 보여주고 물어본다.**
3. **"언제 다시 볼지"는 그 메모 파일 안에 글자로 적힌다.** 앱이 빨리 찾으려고 잠깐 만들어 두는 목록은 사본일 뿐이라 지워져도 되살아난다.

**대화가 날아가지 않게(레고 요청으로 추가).** 대화하는 동안 앱이 갑자기 꺼지는 일이 생겨도 내용이 사라지지 않도록, 앱 안쪽 임시 자리에 **하다 만 대화를 잠깐 적어 둔다.** 이건 메모장(볼트)에 생기는 파일이 아니고, **대화를 정상적으로 닫거나 앱을 정상적으로 끄면 바로 지워진다.** 갑자기 꺼졌을 때만 남아 있다가, 다음에 켜면 "이전에 하다 만 대화가 있어요. 이어서 볼까요?"라고 물어본다. 싫다고 하면 그 자리에서 지운다. 이 기능이 부담스러우면 설정에서 끌 수 있다(처음엔 켜져 있음). **정식 메모로 남기는 건 여전히 "노트로 남기기"를 눌렀을 때만 된다.**

**설정 관련 한 가지.** 대화할 때 "한 번에 보낼 수 있는 글자 수"를 너무 작게 줄이면 보낼 자리가 없어진다. 그럴 땐 잘린 채로 보내지 않고 "이 값이 너무 작습니다"라고 알려 준다.

**이번에 안 하는 것**: 알림 배너, 공부 통계 그래프, 여러 기기 맞추기, 그림·표를 그림째로 카드에 넣기, 말로 하는 공부, 뜻으로 찾기 도입.

## RALPLAN-DR 요약 (deliberate)

### 설계 원칙 5개

1. **원본 불변 · 산출물은 새 파일.** 쓰기는 신규 마크다운 노트 생성뿐이고 "제안 → 사용자 확인 → 실행"을 거친다. (임시 초안은 노트가 아니며 §4.7의 별도 수명 규칙을 따른다.)
2. **진실의 출처는 학습 노트 파일 전체(frontmatter + 항목 앵커), SQLite는 버려도 되는 사본.**
3. **기존 파이프라인 최대 재사용, 새 외부 도구·새 변환기 금지.**
4. **근거 없는 생성 금지.**
5. **얇은 슬라이스 + 실사용 게이트.** S0은 필수 관문, S1 이후 순서는 레고 결정(**확정: S3 → S2**).

### 결정 근거 top 3 (코드로 확인)

1. **복습 데이터를 `searchindex.sqlite`에 넣으면 안 된다** — tokenizer 불일치 시 `DROP TABLE`, 스키마 실패 시 **DB 파일 삭제 후 재생성**(`SearchIndex.swift:29-49`).
2. **위치 규약은 이미 있다** — `RagLocation`의 `.line`/`.page`(1-based)/`.unknown`, `RagPassageExtractor.pdfPassage`가 `PDFDocument` 직접 순회로 `.page(i+1)` 생성(`:71-88`).
3. **스트리밍/비스트리밍 타임아웃 계약이 다르다** — `ask(...timeout:)`은 콜별(위키 300초), **`askStream`은 액터 상수 120초·콜별 파라미터 없음**(`ClaudeService.swift:57, 186-278`), 취소는 `onTermination`에서 `work.cancel()`+`process.terminate()`.

### 실행 가능한 대안

**A — 하나의 우산 + 단계별 슬라이스(채택)** / **B — 4개 독립(기각)** / **C — 프리셋만(A의 S0 필수 관문으로 흡수)**.

## Summary

"학습도우미"를 **하나의 우산 기능 + 4개 슬라이스(S0~S3)**로 만든다. 코어는 `StudyService`(actor). 입력은 `StudySourceLoader`의 **위치 태그 세그먼트 배열**, AI는 `AIRouterService` 주입. 산출물은 항상 새 마크다운 노트이고 **SSOT = 노트 파일 전체**, `studyindex.sqlite`는 재생성 가능한 캐시다. 대화는 앱이 매 턴 컨텍스트를 재조립하며 **예산은 조립 후 최종 문자열 기준으로 강제되고 어떤 설정값에서도 결정적으로 끝난다**. 대화 본문은 여전히 **볼트에 자동 저장되지 않으며**, 다만 **크래시 대비 임시 초안(앱 지원 폴더 단일 파일, 정상 종료 시 삭제, 복구는 사용자 확인 후)**을 기본 ON으로 둔다. **착수 순서는 S0 → S1 → S3 → S2로 확정됐다.**

**SSOT = 학습 노트 파일 전체 = frontmatter + 모든 항목 앵커.** 항목별 상태는 **앵커 소유**, frontmatter `study_due`는 파생 힌트. 불일치 시 앵커가 이긴다. `studyindex.sqlite`는 재생성 가능한 캐시.

#### 3.2 식별자 소유권
| 식별자 | 소유 | 범위 | 용도 |
|---|---|---|---|
| `study_id` | frontmatter | 노트당 1개(UUIDv4) | 노트 정체성·그룹 키 |
| `item_uid` | 항목 앵커 | 항목당 1개(UUIDv4) | **전역 기본키** |

#### 3.3 앵커 정규 문법 (정확히 1줄, 항목 제목 바로 위)
```
<!-- study item=<uuid> src=<percent-encoded-relpath> loc=<locator> due=<YYYY-MM-DD> ivl=<정수일> ease=<x.xx> reps=<정수> lapses=<정수> -->
```
키=값·단일 공백·**값에 공백 금지**·키 순서 고정. `loc` = `p12` / `p12-14` / `l345` / `-`, 모두 1-based. 미지 키는 보존하되 무시. 위반 줄은 건너뛰고 경고 1건(크래시·자동수정 금지).

#### 3.4 항목 필수 필드
- **카드**: `### [카드] 제목` · 불릿 1~3개 · `> 근거: [[loc]] "발췌"` 1개.
- **문제**: `### [문제 n] 요지` · `type` · `Q:` · (mcq면 보기 3~5) · `A:` · `해설:` · 근거 1개.
- **문항마다 자기 `loc`.**

#### 3.5 frontmatter 키
`study_id` · `study_kind` · `study_source` · `study_source_kind` · `study_created` · `study_items` · `study_due`(파생).

#### 3.6 중복·충돌·손상 정책
| 상황 | 처리 |
|---|---|
| `item_uid`가 두 파일에 존재 | **mtime 최신 승자**, 나머지 제외 + 안내. 파일 자동 수정 금지 |
| **mtime 동일** | **정규화 절대경로 오름차순(POSIX) 선순위 승자** — 재빌드 반복 시 동일 |
| 노트 안 중복 uid | 첫 번째만 채택 + 경고 |
| 앵커 파싱 실패·frontmatter/`study_id` 없음 | 항목 0건 취급, 파일 불변 |
| `due` 파싱 실패 | 그 항목만 제외 |
| 채점 직전 파일 변경 | 쓰기 전 재확인 후 불일치면 포기 + 안내 |
| 채점 쓰기 | 앵커 줄만 치환 + 백업 1부 |

#### 3.7 재빌드 범위
설정 `studyFolders`(기본 = 노트 저장 위치 1곳). 등록 폴더 밖 노트는 인덱스에 없다. `.md`만 · 깊이 ≤ 8 · 심볼릭 링크 미추적 · 숨김 폴더 제외 · 상한 20,000 · `study_id` 있는 파일만. 트리거: 앱 시작 1회 · 폴더 변경 · 캐시 없음/실패 · 수동.

#### 3.8 캐시 스키마
`study_items(item_uid TEXT PRIMARY KEY, study_id TEXT, note_path TEXT, kind TEXT, loc TEXT, due REAL, ivl INTEGER, ease REAL, reps INTEGER, lapses INTEGER, scanned_at REAL)` + `INDEX(due)`, `INDEX(study_id)`.

#### 3.9 스케줄링
모름 → `ivl=1`, `ease-=0.20`, `lapses+=1` / 애매 → `ivl=max(1, round(ivl×1.2))`, `ease-=0.05` / 앎 → `ivl=max(1, round(ivl×ease))`, `ease+=0.05`(첫 성공 1일, 두 번째 3일). `ease` [1.30, 2.80], `ivl` 상한 180일. 하루 상한 신규 20·복습 100. 신호는 앱 내 배지만.

#### 3.10 원본 불변
복습 상태는 앱이 만든 학습 노트에만 쓴다. 최초 생성은 제안→확인, 채점 갱신은 자동 저장(재확인 + 백업).

### Q4. 대화형 동반자

#### 4.1 세션 모델
```
StudyChatSession {
  id: UUID
  sourceURL: URL?
  pinnedExcerpt: String
  turns: [(role, text, truncated: Bool)]
  foldedPrefix: String?
  streamTask: Task<Void, Never>?
}
```
메모리에 있고, **크래시 대비 사본만** §4.7의 임시 초안으로 디스크에 잠시 존재한다.

#### 4.2 전송 컨텍스트 예산 — 직렬화 후 기준 + 설정값 전 구간 안전 (변경 없음)

##### 4.2.1 회계 기준
예산은 **`ChatContextAssembler.assemble(...)`이 반환하는 최종 문자열의 전체 길이**로 센다(프리앰블·구역 머리말·역할 라벨·구분선·개행·위치 태그·생략 표기 포함). 반환은 `.assembled(String)` 또는 `.noSend(reason)`이며 **부분 전송은 없다.**

##### 4.2.2 배분 공식
```
1) reserve       = ceil(cap × 0.08)
2) P(프레이밍 고정분)를 먼저 실측
3) if P >= cap → 배분 없이 즉시 .noSend(.capTooSmall)
4) contentBudget = max(0, cap - max(reserve, P))
5) pin=floor(cb×0.60), folded=floor(cb×0.10), recent=floor(cb×0.25), question=floor(cb×0.05)
   remainder = cb - (합)   // 0~3, 항상 pin에 가산
6) if question == 0 → .noSend(.capTooSmall)
```
- 예약은 하한이지 상한이 아니며, 3)의 가드로 음수 예산이 불가능하다.
- 검산: `cap=12,000` → `reserve=960` → `cb=11,040` → `6,624/1,104/2,760/552`.
- **허용 cap**: 양의 정수 전부(no-send 규칙이 하한을 대신). UI 권장 4,000~40,000·기본 12,000, 0 이하는 저장 거부.
- 핀 바닥값은 **`min(1,000, pin)`**.

##### 4.2.3 트리밍 — 유한 진행·종료 보장
| 단계 | 동작 | 하한 |
|---|---|---|
| 1 | 접힌 요약 뒤에서 절단(머리말 포함 제거) | 0자 |
| 2 | 최근 턴을 오래된 것부터 통째 제거 | 0턴 |
| 3 | 핀 발췌 뒤에서 절단 | `min(1,000, pin)` |
| 4 | 이번 질문을 `question`자로 절단 + 경고 | `question` |

각 단계는 내부 **100자 블록 루프(최대 `ceil(길이/100)`회)** 후 **정확히 한 번만** 시도되고, **0자를 제거해도 다음 단계로 진행**한다. 단계 사이 재측정 후 `cap` 이하가 되면 즉시 `.assembled`. **4단계 후에도 초과면 즉시 `.noSend(.cannotFitAfterTrim)`.** 루프 조건은 "cap 밑으로 내려갈 때까지"가 아니라 **"단계 목록 소진까지"** — 항상 종료한다.

##### 4.2.4 사후조건
`.assembled(s)`면 `s.count ≤ cap`. 그 외는 전부 `.noSend`. 같은 입력·설정 → 같은 반환값.

##### 4.2.5 카드·퀴즈 청크 예산
`StudyChunker`도 위치 태그·구분자 포함 길이로 계산. 프롬프트 본체는 `-p` 인자라 청크 예산에 미포함.

#### 4.3 압축 — 결정적 절단 기본, AI 요약 옵트인 (변경 없음)
기본은 `역할: 앞 200자 + "…"` 결정적 접기(AI 호출 0). `studyChatAISummary`(기본 OFF)일 때만 비스트리밍 `ask(...timeout:120)` 1회 + 1회 재시도로 5줄 요약, 실패 시 **조용히 결정적 접기로 폴백**. 대체는 조립 시점에만. 세션 메모리·전송 컨텍스트·요약 결과는 **볼트에 저장되지 않는다**(§4.7 임시 초안은 별개).

#### 4.4 타임아웃·재시도·취소 (변경 없음)
대화 턴 = `askStream` → **120초 고정, 콜별 타임아웃 없음, 자동 재시도 없음**. 300초+1회 재시도는 카드·퀴즈 전용. 취소는 `StudyChatService`가 `Task`를 보관·`cancel()`, 뷰는 `stop()`만 호출.

#### 4.5 멀티턴 구현 방식 (변경 없음)
`claude -p`는 단발 무상태. 앱이 매 턴 재조립·재전송. CLI 세션 재개 플래그는 전례가 없어 채택하지 않는다(S3 조사만).

#### 4.6 "응답 영구 저장 안 함" 원칙 (경계 재확인)
원칙의 뜻은 **"앱이 사용자 모르게 AI 출력을 볼트에 쌓지 않는다"**이다. 정식 노트는 여전히 "노트로 남기기"를 눌러야만 생긴다. §4.7의 임시 초안은 볼트 밖·수명 한정·설정 OFF 가능이므로 이 원칙과 충돌하지 않는다(§4.7.1 표).

#### 4.7 크래시 대비 임시 초안 (신설 — 레고 확정 ON)

##### 4.7.1 무엇이 다른가 (「이번에 하지 않을 것 10」과의 경계선)

| 구분 | ❌ 금지(항목 10): 자동 영구 저장 | ✅ 이번에 켜는 것: 크래시 임시 초안 |
|---|---|---|
| 저장 위치 | 볼트 안 마크다운 노트 | **앱 지원 폴더**(`~/Library/Application Support/CmdMD/`) 단일 JSON |
| 사용자에게 보이는가 | 노트 목록·검색·동기화에 나타남 | 앱 UI·검색·색인 어디에도 안 나타남. Dropbox/볼트 동기화 대상 아님 |
| 수명 | 영구 | **정상 종료 시 삭제**, 14일 만료, 세션 1개분만 |
| 생성 조건 | 앱이 알아서 | 대화 중 자동, 단 **설정에서 OFF 가능**(`studyChatCrashRecovery`, 기본 ON) |
| 정식 노트가 되려면 | — | **"노트로 남기기"를 눌러야만** (원칙 불변) |
| 복구 | — | **사용자 확인 후에만**(자동 복구 없음) |

##### 4.7.2 저장 위치·형식
- 경로: `appDir/study-chat-draft.json` (단일 파일, **세션 1개분**). `appDir`은 `AppState.init`이 이미 만드는 데이터 디렉터리이며, 같은 폴더에 JSON 상태 파일을 두는 전례가 있다(`VaultService`의 `vault-bookmarks.json`).
- 형식: `Codable` JSON — 마크다운이 아니라 구조가 필요하다(역할·순서·핀 발췌·원본 경로·시각).
```
StudyChatDraft {
  schemaVersion: Int          // 1
  sessionId: UUID
  sourcePath: String?         // 원본 파일 경로(없을 수 있음)
  sourceDisplayName: String?  // 복구 프롬프트 표시용
  pinnedExcerpt: String
  turns: [{ role: String, text: String, truncated: Bool }]
  updatedAt: Date
  appBuild: String
}
```
- **볼트 마크다운이 아니다.** 사용자가 보는 노트 파일과 완전히 분리된다.

##### 4.7.3 쓰는 시점 (디스크 I/O 비용 고려)
- **매 토큰 델타마다 쓰지 않는다.** 스트리밍은 초당 수십 회 상태가 바뀌므로 매번 쓰면 불필요한 디스크 부하가 크다.
- 규칙: **(a) 턴이 끝날 때마다 1회**(스트림 정상 종료·중단·에러 모두 포함) + **(b) 스트리밍 중에는 최대 5초 간격의 디바운스 저장**(부분 응답도 살리기 위해). 두 경우 모두 **직전 저장 이후 내용이 실제로 바뀐 경우에만** 쓴다.
- 근거: 대화 1세션은 보통 수 KB~수십 KB라 5초 디바운스 쓰기는 부하가 미미하고, 크래시 시 손실은 **최대 5초분(대개 문장 하나)**로 제한된다.
- **원자적 교체**: 임시 파일에 쓴 뒤 `FileManager.replaceItemAt`으로 교체한다 — 쓰는 도중 강제 종료돼도 **이전 초안이 손상되지 않는다.**
- 백그라운드 우선순위 `Task`에서 수행하며 메인 스레드를 막지 않는다. 쓰기 실패는 **조용히 무시**(대화 흐름을 끊지 않는다) + 로그 1줄.

##### 4.7.4 지우는 시점
다음 중 어느 하나라도 발생하면 초안 파일을 삭제한다.
1. 대화 화면/세션을 **정상적으로 닫을 때**
2. **"노트로 남기기"** 저장이 완료됐을 때(정식 노트가 생겼으므로 초안 불필요)
3. **앱 정상 종료** 시(종료 훅)
4. **새 대화 세션을 시작할 때**(이전 초안을 복구했거나 거부한 뒤)
5. 복구 프롬프트에서 **[지우기]** 를 눌렀을 때(즉시)
6. 설정에서 `studyChatCrashRecovery`를 **OFF로 바꿨을 때**

삭제 실패해도 크래시하지 않는다. → 따라서 **정상 경로에서는 디스크에 대화가 남지 않는다**(AC #20).

##### 4.7.5 복구 흐름
1. **앱 시작 즉시가 아니라, 학습도우미 대화 화면에 처음 들어갈 때** 초안 존재를 확인한다(관련 없는 작업 중에 방해하지 않기).
2. 유효성 판정: `schemaVersion` 일치 · JSON 파싱 성공 · `updatedAt`이 **14일 이내** · 턴이 1개 이상. 하나라도 어긋나면 **프롬프트 없이 조용히 삭제** + 로그.
3. 유효하면 시트: **"이전에 하다 만 대화가 있어요(《원본 이름》, 7월 30일 21:14). 이어서 볼까요?"** → **[이어서 하기]** / **[지우기]**.
4. **[이어서 하기]**: 핀 발췌·턴 전부를 세션에 복원한다. 원본 파일 경로가 사라졌으면 **파일을 다시 읽지 않고** 저장된 발췌 텍스트를 그대로 쓰고 "원본 파일을 찾지 못해 대화 내용만 복원했습니다" 안내를 붙인다.
5. **[지우기]**: 즉시 삭제, 같은 프롬프트가 다시 뜨지 않는다.
6. **자동 복구는 없다** — 기존 "제안 → 확인 → 실행" 원칙과 동일.

##### 4.7.6 민감성·개인정보
초안에도 교재 발췌와 대화가 담긴다. 완화 장치: **단일 파일** · **정상 종료 시 삭제** · **14일 만료** · **설정에서 OFF 가능(끄는 즉시 기존 초안 삭제)** · **앱 지원 폴더라 볼트/클라우드 동기화 대상이 아님** · 앱 내 검색·색인 대상 아님. 이 목록을 설정 화면 도움말에 한 줄로 요약해 노출한다.

##### 4.7.7 책임 분리
- **신규 파일 `Sources/Services/StudyChatDraftStore.swift`로 분리한다.** `StudyChatService`는 세션·스트림·취소를 담당하고, 초안은 **디스크 수명주기(쓰기·원자 교체·만료·삭제)**라 관심사가 다르다. 분리하면 순수 판정 함수(만료·디바운스 게이트·인코딩 라운드트립)를 CLI 없이 단위 테스트할 수 있다.
- `StudyChatService`는 "턴 종료/5초 경과" 신호만 보내고, 저장 여부·시점 판단은 Store가 한다.

### Q5. 문서 형태 + 출처 위치 (변경 없음)

#### 5.1 진입 계약
```
enum StudyLocator { case page(Int); case pageRange(Int, Int); case line(Int); case unknown }
struct StudySegment { let text: String; let locator: StudyLocator }
struct StudyChunk { let body: String; let coveredLocators: [StudyLocator]; let charCount: Int }
```

페이지·줄 모두 1-based. PDF 페이지 = PDFKit 인덱스 + 1 → UI에 "파일 기준 N쪽".

#### 5.2 종류별 세그먼트
| 종류 | 본문 출처 | locator | 부분 선택 범위 |
|---|---|---|---|
| PDF | `PDFDocument` 직접 순회 | `.page(i+1)`(빈 페이지는 OCR 보강, 그래도 비면 스킵) | `pageRange` |
| 마크다운·텍스트·eml | 줄 단위 + 헤딩 경계 | `.line(첫 줄)` | `lineRange` |
| office(2026-08-01 I3) | kordoc 변환 후 이 서비스가 다시 헤딩 경계로 구간 분할 | `.unknown`(원본 위치 불명 — 변경 없음) | `sectionRange`(변환된 글의 N번째 제목 구간, 헤딩 없으면 1구간=전체) |
| 이미지(OCR) | `OCRService` | `.unknown` | `wholeFile`만(나눌 단위 없음) |
| media | 제외(짝꿍 노트가 있으면 마크다운 취급) | — | — |
| quickLook | 제외 | — | — |

#### 5.3 청크 → 인용 매핑
위치 태그 `[[p12]]`/`[[l345]]`/`[[?]]` 부착 → 파서가 복원 → **`coveredLocators`에 없는 태그는 `.unknown` 강등 + `invalidCitations`**.

#### 5.4 재사용 주장 정정
본문 획득은 최대한 재사용, 위치 메타데이터가 필요한 PDF·텍스트는 `StudySourceLoader`가 기존 API로 자체 구성.

## 출력 계약 — 카드·퀴즈 생성 (변경 없음)

### O1. 출력 문법
카드:
```
### [카드] 제목
- 핵심 1
- 핵심 2
> 근거: [[p12]] "교재 원문 발췌"
```
문제:
```
### [문제 3] 문항 요지
type: mcq
Q: 질문 본문
1) 보기 A
2) 보기 B
3) 보기 C
4) 보기 D
A: 2
해설: 왜 2번인지
> 근거: [[p12]] "교재 원문 발췌"
```

### O2. 필수 필드
카드 = 제목·불릿 ≥1·근거 1 / 문제 = 제목·`type`·`Q:`·(mcq면 보기 3~5)·`A:`·`해설:`·근거 1. 누락 시 **그 항목만 폐기**.

### O3. 절단 상한
불릿 개수 3(4번째부터 폐기) · 불릿 120자 · 해설 600자 · 발췌 200자 · 제목 80자 · 대화 접기 1턴 200자.

### O4. 인용 검증
청크 밖 태그 → `.unknown` 강등 + `invalidCitations` / 발췌 부분문자열 불일치 → `unverifiedQuote` 표시(폐기 안 함) / 미리보기에 `유효 인용 k / n`.

### O5. 실패·재시도·부분 성공
유효 0건 → 같은 청크 1회만 재요청 → 두 번째도 0건이면 그 청크 실패 + 원문 보관. 전체 실패는 모든 청크 실패 시에만.

### O6. 다중 청크 누적
청크당 `ceil(N/C)` · 초과분 앞에서부터 N개 채택 · 제목 정규화 중복 폐기 · `item_uid`는 `StudyNoteWriter`가 발급.

## ADR — 학습도우미(Study Helper) 기능 도입

### Decision

cmdALL에 "학습도우미"를 **하나의 우산 기능 + 4개 슬라이스(S0 프리셋 실험 → S1 코어/카드/퀴즈 → S3 대화형 동반자 → S2 복습 관리)**로 도입한다. S0은 필수 관문(우회 없음)이고, S1 완료 후 S3와 S2는 서로 독립이며 착수 순서는 레고가 S3 우선으로 확정했다. 복습 데이터의 진실 출처(SSOT)는 학습 노트 파일 전체(frontmatter + 항목 앵커)이며, `studyindex.sqlite`는 재생성 가능한 파생 캐시일 뿐이다. 대화형 동반자는 무상태 `claude -p` 위에 앱이 매 턴 컨텍스트를 조립·전송하고, 전송 예산은 직렬화 후 최종 문자열 길이를 기준으로 결정적으로 강제된다(초과 시 잘라서 보내지 않고 전송 자체를 하지 않는다). 크래시 대비 임시 대화 초안 저장을 기본 ON으로 추가하되, 볼트 밖 단일 파일·정상 종료 시 삭제·14일 만료·설정 OFF 가능이라는 조건으로 "동의 없는 영구 저장 금지" 원칙과 명확히 구분한다.

### Drivers

1. **파괴적 재구성 위험 회피** — 복습 데이터를 언제든 DROP·재생성될 수 있는 `searchindex.sqlite`에 절대 넣지 않는다(`SearchIndex.swift:29-49`).
2. **신규 패키지 의존성 0** — `Yams`·`SQLite3`·`PDFKit`/`Vision`·`Foundation JSONEncoder` 등 이미 쓰고 있는 것만 재사용한다.
3. **provider 중립** — AI 호출은 전부 `AIRouterService`/`any ClaudeAsking` 주입 경로를 통해서만 이뤄진다.
4. **업스트림(CmdMD) 머지 마찰 최소화** — 신규 로직은 `Study*` 접두사 별도 파일에 모으고 기존 파일은 최소 배선만 한다.
5. **비개발자 1인 운영에 맞는 안전장치** — 크래시 없이 한국어 안내, 실행 취소가 쉬움(생성 파일 삭제만으로 원상복구), 실사용 검증 없이 다음 단계로 넘어가지 않는 게이트.

### Alternatives considered

- **A — 하나의 우산 + 단계별 슬라이스(채택)**: 4개 기능이 최종적으로 포맷·파이프라인을 공유하므로(카드/문제는 동일 노트 스키마, 복습은 그 스키마에 기생) 처음부터 하나의 데이터 모델로 설계하고 실사용 게이트로 무모한 전진을 막는다.
- **B — 4개를 완전히 독립적으로 구현**: 기각. 나중에 복습 기능이 카드·문제와 통합되려면 포맷 통일 리팩터가 필연적으로 발생해 이중 작업이 된다.
- **C — 프리셋(버튼)만 우선 검증 후 재논의**: 옵션 A의 S0 필수 관문으로 흡수됨 — 별도 대안이 아니라 A의 첫 단계로 편입.

### Why chosen

옵션 A는 (1) 복습·카드·퀴즈가 결국 같은 노트 스키마를 공유해야 하는 구조적 필연성, (2) S0이라는 저비용 실사용 검증을 먼저 거쳐 "만들었는데 안 쓴다"는 리스크(pre-mortem 시나리오 3)를 선제 차단하는 점, (3) S2·S3가 실제로 독립적이어서 레고가 원하는 순서(대화 먼저)를 구조 변경 없이 그대로 수용할 수 있었던 점에서 B·C 대비 명확히 우월했다. 5라운드 컨센서스 검토(Architect·Critic)를 거치며 복습 데이터 모델(SSOT·식별자·충돌정책), 출처 위치 확보 경로(PDF 페이지 경계), 대화 컨텍스트 예산의 경계조건(설정 가능한 상한에서의 음수 예산·무한루프 방지)까지 전부 코드 근거로 검증됐다.

### Consequences

- **얻는 것**: 자격증 교재를 포함한 다양한 문서 형태(PDF·한글·오피스·이미지·마크다운)로 카드·퀴즈를 만들고, 복습을 챙기고, 대화하며 공부할 수 있는 기능이 새 파일 위주로 추가되며 기존 1,068개 테스트·업스트림 머지 경로에 미치는 영향이 최소화된다.
- **치르는 비용**: 신규 파일 15개 이상(`Study*` 서비스·모델·뷰, `StudyChatDraftStore` 포함), 총 개발 기간 S0~S3 합산 약 13~18일, `AppState`/`Settings`/`CmdMDApp` 등 기존 파일에 최소 배선이 들어간다.
- **감수하는 제약**: PDF가 아닌 오피스·이미지 문서는 출처 위치가 `.unknown`(파일 열기까지만) 수준으로, 페이지 단위 점프가 안 된다. 대화 크래시 임시 초안은 최대 14일·볼트 밖에 사용자 데이터(교재 발췌 포함)를 잠시 보관한다는 프라이버시 트레이드오프가 있으나 설정으로 끌 수 있다.
- **후속 영향**: `docs/todolist.md`·`CmdMD-fork_prd.md`(§3.15) 갱신 필요. S2 이후 통계/알림 같은 확장은 이번 범위 밖으로 명시적으로 유보됨.

### Follow-ups

1. S1/S3 착수 전 코드 조사 3건: 스캔 PDF 페이지 단위 OCR 폴백 실용 속도, 학습 노트 기본 저장 위치(교재 옆 `학습/` vs 지정 볼트 폴더) 확정, 앱 정상 종료 훅(`applicationWillTerminate` 계열)이 실제로 크래시 초안 삭제에 쓰일 수 있는지 코드로 재확인(추정 금지).
2. S0 완료 후 레고의 "쓸 만하다" 실사용 판정 3회 확보 — 이 판정 없이는 S1 착수 금지.
3. S2 착수 시점 재확인 — S1·S3 완료 + 산출 노트 10개 이상 + 2주 실사용 증거 충족 여부.
4. 승인 후 정식 문서화 — `docs/superpowers/specs/2026-07-31-study-helper-design.md`(설계) → `docs/superpowers/plans/2026-07-31-study-helper.md`(구현 계획) 두 파일로 분리 기록.

## Pre-mortem — 3개 시나리오

**1 — "교재를 통째로 보내서 다 터졌다".** 범위 선택 필수화 · 직렬화 포함 예산 · 청크 순차 처리 · 사전 분량 표시 · 카드·퀴즈만 300초 + 1회 재시도 · 부분 성공 허용.

**2 — "복습 기록이 통째로 날아갔다".** SSOT = 노트 파일 전체 · 캐시 물리 분리 · 전역 키 `item_uid` · 등록 폴더 스캔 · 앵커 줄만 치환 + 백업 + 쓰기 전 재확인 · 중복은 mtime → 경로 순서의 결정적 승자.

**3 — "다 만들었는데 안 쓴다".** S0 필수 관문 · 진입 마찰 최소화 · "오늘 복습 N" 배지 · **레고가 실제로 원한 대화(S3)를 복습보다 먼저** · 슬라이스마다 2주 실사용 체크박스.
