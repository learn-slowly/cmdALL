# 문제 풀기 화면 — 설계

- 날짜: 2026-08-05
- 요청: 레고 "학습도우미 관련해서 `/Users/ahbaik/coding/mediaedu-quiz` 확인해서 최대한 비슷하게 구현해봐"
- 참고한 것: `mediaedu-quiz`(배포 사이트) + `mediaedu-quiz-build`의 `quiz_template.html`·`SKILL.md`

## 왜 — 지금 빠져 있는 한 칸

학습도우미는 문제를 **만들어 노트로 저장**하고, 복습 화면은 그 항목을 **한 장씩 넘기며 스스로
"모름/애매/앎"을 누르는** 방식이다. 즉 5지선다를 **눌러서 푸는 자리가 없다.** 문제를 만들어 놓고도
정답을 스스로 채점해야 하니, 만든 문제집이 "다시 안 보는 노트"로 끝나기 쉽다.

mediaedu-quiz는 그 반대다. 문제집을 만드는 기능은 없고(밖에서 만들어 넣는다) **푸는 화면만** 있는데,
그 화면이 아주 잘 다듬어져 있다. 두 프로젝트는 정확히 서로의 빈칸을 채운다.

## ⚠️ 설계 변경(2026-08-05) — 문제집을 복제하지 않는다

레고 지적: "이미 문제가 다 볼트에 있는데 문제집을 가져온다는 게 어떻게 하는 거야?"

처음 계획은 볼트의 문제집 md를 읽어 **학습 노트로 새로 써서** 앱 형식으로 옮기는 것이었다
(= 5,000문항을 한 벌 더 만든다). 그 계획을 버린다.

같은 날 미디어교육사 100제에서 **정답이 두 곳(해설·맨 뒤 요약표)에 적혀 있다가 한쪽만 낡아
74곳이 어긋난** 사고를 고쳤다. 문제집을 통째로 복제하면 그 병을 5,000문항 규모로 다시 만든다.
전역 문서 규칙의 "같은 사실은 한 곳에만 쓰고 나머지는 가리킬 것"이 여기에도 그대로 적용된다.

**대신 교재 진도 관리와 같은 방식을 쓴다** — 원본은 손대지 않고 **기록장만 따로** 둔다.

| | 원본 문제집 md | 기록장(신규) |
|---|---|---|
| 무엇 | 발문·보기·정답·해설(진실의 출처) | 문항 번호 + 복습 상태(`due`/`ivl`/`ease`/`reps`/`lapses`) |
| 누가 고치나 | 기존 생성 스크립트·검사 도구 | 앱이 채점할 때만 |
| 크기 | 그대로 | 문제집 하나당 앵커 줄 N개 |

화면에 문제를 띄울 때는 **원본을 그때그때 읽는다**(`QuizImportParser`). 그래서 원본을 고치면
앱에도 곧바로 반영되고, 정답이 두 곳에 적히는 일이 없다.

### 기록장 형식 (진도 노트 `study_progress_id` 전례를 따른다)

저장 위치: `<학습 폴더>/문제집기록/<원본파일이름>.md`

```markdown
---
study_quiz_id: <uuid>
study_quiz_source: <percent-encoded 상대경로>   # 원본 문제집 md
study_quiz_book: <percent-encoded 상대경로>     # 교재 원본(쪽 열기용, 있을 때만)
study_quiz_items: 100
study_updated: 2026-08-05
---

<!-- quiz item=<uuid> n=1 due=2026-08-05 ivl=0 ease=2.50 reps=0 lapses=0 -->
<!-- quiz item=<uuid> n=2 due=2026-08-07 ivl=2 ease=2.55 reps=1 lapses=0 -->
```

- 앵커 키는 기존 학습 노트와 같되 `src`/`loc` 대신 **`n`(문항 번호)** 을 쓴다 — 본문이 원본에 있으므로.
- 미지 키 보존·쓰기 직전 재확인·백업 1부 등 기존 채점 쓰기 규약을 그대로 따른다.
- 원본이 바뀌어 문항 수가 달라지면 번호로 다시 맞추고, 사라진 번호의 기록은 남겨 둔다(지우지 않는다).

### 이 변경으로 달라지는 것

- `Q0`의 목표가 "학습 노트로 변환"에서 **"기록장 만들기 + 원본 읽기"** 로 바뀐다.
- `StudyNoteWriter`로 문제 노트를 쓰지 않는다(가져오기 경로에서는). 이미 넣은
  "근거 인용이 비면 `> 근거:` 줄 생략"은 그대로 둔다 — 손으로 만든 문제에도 유효한 개선이다.
- `StudyIndex`(복습 캐시)는 학습 노트 앵커를 훑는데, 기록장도 같은 방식으로 훑게 넓힌다.

## mediaedu-quiz에서 무엇을 가져오나

`quiz_template.html`을 그대로 읽어 화면 요소를 하나씩 대조했다.

| mediaedu-quiz | cmdALL에서 | 판정 |
|---|---|---|
| 문제 카드 = 번호 · 형식 배지 · 발문 · 보기 5개 | 문제 노트 항목 하나 | **가져옴** |
| 보기를 누르면 **즉시 채점** — 정답 초록, 내 오답 빨강, 나머지 흐리게, 다시 못 누름 | 신규 | **가져옴(핵심)** |
| 상단 고정 바 — 푼 문제 n/총 · 맞음 · 틀림 + 진행 막대 | 신규 | **가져옴** |
| 형식별 탭(A 옳은것 / B 옳지않은것 / C 빈칸 …) | 항목의 `type` 값으로 같은 탭 | **가져옴(값이 있을 때만)** |
| "해설 보기" 접기/펴기 | 신규 | **가져옴** |
| `📖 교재 p.NNN 열기` | `openStudySource`가 이미 함 | **재사용** |
| `💬 물어보기` (그 문제 맥락을 담아 AI에게) | 학습 대화(S3)가 이미 있음 | **재사용** |
| 하단 고정 바 — 전체 / 틀린 것만(n) / 기록 초기화 | 신규 | **가져옴(초기화는 뜻을 바꿈, 아래)** |
| 풀이 기록을 브라우저에 저장 | **노트 앵커의 복습 값에 기록** | **바꿔서 가져옴 — 더 낫다** |
| 문제집 만들기(6형식 100문항) | 학습도우미가 이미 함 | 그대로 둔다 |
| 찍기 방지 검사(보기 길이·정답 쏠림) | 신규 | **2단계로 미룸**(아래 "이번에 하지 않을 것") |

### 두 곳이 갈리는 지점 — 풀이 기록

mediaedu는 브라우저에 `{문제번호: 맞음/틀림}`만 남긴다. 다시 풀면 덮인다.

cmdALL은 이미 항목마다 **다음 복습일·간격·난이도**를 노트 앵커에 쌓고 있다(`due`/`ivl`/`ease`/
`reps`/`lapses`). 그래서 **문제를 맞히면 `앎`, 틀리면 `모름`으로 그 자리에서 채점 처리**한다.
결과: **틀린 문제가 며칠 뒤 복습 화면에 저절로 다시 나온다.** mediaedu에는 없는 연결이고,
새 저장 형식도 필요 없다(기존 앵커 그대로).

그래서 하단 "기록 초기화"는 뜻을 바꾼다 — 복습 이력을 지우면 손해이므로 **"이번 판 다시 풀기"**
(화면의 정오 표시만 지움, 노트의 복습 기록은 그대로)로 한다. 파일을 지우지 않는다는 기존 원칙과도 맞다.

## 이미 있는 재료 (새로 모을 것 없음)

문제 노트는 이미 이런 모양으로 저장된다(`StudyNoteWriter.questionBlock`).

```markdown
<!-- study item=<uuid> src=<교재 상대경로> loc=p12 due=2026-08-05 ivl=0 ease=2.50 reps=0 lapses=0 -->
### [문제 1] 제목
type: mcq
Q: 발문
1) 보기1
2) 보기2
3) 보기3
A: 2
해설: 한 줄 설명
> 근거: [[p12]] "교재 원문 발췌"
```

- `StudyNoteParser`가 항목별로 `title` + `body`(위의 `type:`부터 `> 근거:`까지 원문)를 이미 뽑아 준다.
- `StudyIndex`(SQLite 캐시)에 `note_path`·`kind`·`loc`·`src_path`·복습 값까지 이미 들어 있다.
- `StudySourceLink`가 `loc`으로 **교재 원본의 그 쪽/줄**을 연다.
- 채점 쓰기(앵커 한 줄 치환 + 백업 1부 + 쓰기 직전 재확인)는 `AppState+StudyReview`에 이미 있다.

**즉 새로 만들 것은 "본문 한 덩어리를 보기 목록으로 되돌리는 파서"와 "푸는 화면" 둘뿐이다.**

## 실측 — 레고님 실제 노트로 세어 봤다 (설계가 바뀐 지점)

착수 전에 볼트에 있던 실제 문제 노트(`inbox/미디어교육사 교재_개정판(2025년) 문제.md`, 50문항,
2026-08-01에 cmdALL이 만든 것)를 그대로 세었다.
**이 파일은 2026-08-05에 지웠다** — 같은 교재의 100제 5,000문항과 중복이고 한 번도 복습하지
않은 상태였다(볼트 커밋 `c1eff4f`, 되돌리려면 그 직전 판). 아래 수치는 그때의 실측 기록이다.

| 형식 | 개수 | 푸는 방법 |
|---|---|---|
| `mcq` | 40 (80%) | 보기를 눌러서 |
| `OX` | 6 (12%) | **O·X 두 버튼으로** |
| `단답` | 4 (8%) | 눌러서 못 푼다 — 정답 보고 스스로 채점 |

**눌러서 풀 수 있는 문항 92%.** 정답 표기는 50개 전부 깔끔했다(`A: 2` / `A: O` / `A: medius`).

여기서 설계가 두 군데 바뀐다.

1. **`OX`는 mediaedu에 없는 형식인데 레고님 노트의 12%다.** 보기가 없다고 버리면 안 된다 →
   **O·X 두 버튼**을 보기처럼 눌러 채점하는 갈래를 따로 만든다.
2. **보기는 5개가 아니라 4개다.** mediaedu는 5지선다 고정이지만 cmdALL 학습도우미는 4개를 만든다
   → 화면은 **보기 개수를 세어 그리는** 방식이어야 한다(①~⑤ 고정 금지).

## 새로 만드는 것

### 1. `StudyQuizParser` (순수 함수, 신규)

`ParsedItem.body` 한 덩어리 → 발문·보기·정답·해설·근거로 나누고, **푸는 방법 세 갈래** 중
하나로 판정한다.

| 줄 | 뽑는 값 |
|---|---|
| `type: …` | 형식(탭 이름) |
| `Q: …` | 발문 |
| `1) …` `2) …` … | 보기(순서대로, **개수는 세어서**) |
| `A: …` | 정답 |
| `해설: …` | 해설 |
| `> 근거: [[p12]] "…"` | 근거 발췌(위치는 앵커의 `loc`을 쓴다) |

**푸는 방법 판정**

1. **보기 눌러 풀기** — 보기가 2개 이상이고 정답 번호를 알아낼 수 있을 때.
   정답 표기가 흔들릴 수 있으므로 순서대로 시도한다:
   숫자만(`2`) → `2) 보기 내용` → `②` 같은 동그라미 → 보기 문장과 공백 무시 일치.
2. **O·X 눌러 풀기** — 보기가 없고 정답이 `O`/`X`/`○`/`×` 한 글자일 때.
3. **스스로 채점** — 위 둘 다 아닐 때(단답 등). 정답·해설을 보여주고 기존 복습 방식대로
   "모름/애매/앎"을 누른다. **못 읽는 문제 때문에 화면이 비지 않게** 하는 안전망이기도 하다.

### 2. `QuizSession` 상태 (`AppState`)

- 지금 푸는 문제집(노트 경로) · 문제 목록 · 내가 고른 답 · 정오 · 해설 펼침 여부 · 필터
- 필터: 전체 / 안 푼 것 / 틀린 것만 / 형식별
- **앱을 껐다 켜면 화면의 정오 표시는 사라진다**(복습 기록은 노트에 남아 있으므로 손실 없음).

### 3. `StudyQuizView` (화면, 신규)

두 단계다.

- **문제집 고르기** — 문제 노트 목록(챕터별 이름 · 문항 수 · 오늘 복습할 개수 · 교재 이름).
  mediaedu의 첫 화면(목차)에 대응.
- **푸는 화면** — 위 표의 요소 그대로. 상단 통계·진행 막대, 형식 탭, 문제 카드 목록,
  하단 전체/틀린 것만/다시 풀기.

`MainMode`에 `quiz`를 더해 툴바 모드 선택기에 올린다(할일·진도·학습도우미·복습과 같은 방식).

### 4. `StudyIndex` 조회 두 개 추가

- `questionNotes()` — 문제 노트 목록(경로별 문항 수·오늘 몫 개수·교재 경로)
- `items(forNotePath:)` — 그 노트의 항목 전부(노트에 적힌 순서 유지)

### 5. 채점 경로 공통화

`gradeCurrentStudyReviewItem`의 파일 쓰기 부분(백업 → 재확인 → 앵커 치환 → 캐시 갱신)을
`applyStudyGrade(item:outcome:)`으로 뽑아 복습 화면과 문제 풀기 화면이 같이 쓴다.
**동작은 그대로** — 옮기기만 한다.

## 이번에 하지 않을 것

- **웹 배포·HTML 생성.** mediaedu는 정적 사이트라 필요했던 것이고 cmdALL은 앱이다.
- **비밀번호·접속 열쇠 관리.** mediaedu 고유 사정(공개 사이트라 잠가야 함).
- **문제 만드는 규칙 손대기.** 6형식 100문항·섹션 배분 같은 mediaedu 규격은 그 시험 전용이다.
  cmdALL 학습도우미의 프롬프트는 건드리지 않는다.
- **찍기 방지 검사**(보기 길이가 정답만 길지 않은지·정답 번호가 한쪽에 쏠리지 않는지).
  mediaedu에서 가장 값진 교훈이지만 화면이 아니라 **만들 때** 붙는 기능이라 분리한다.
  풀기 화면이 자리 잡은 뒤 2단계로 제안한다.
- **정답 자동 재배치**(쏠린 정답 번호를 섞기). 위와 같은 이유.

## 확인할 위험

- **AI가 만든 문제의 정답 표기가 제각각일 수 있다.** → 파서 5단계 + 실패 시 기존 방식 대체.
  실제 노트로 실측해 몇 %가 풀리는지 보고 필요하면 규칙을 늘린다.
- **틀렸을 때 바로 복습 채점이 되는 게 과할 수 있다.** → 맞음=`앎`, 틀림=`모름`으로만 매기고,
  한 문제를 두 번 눌러 두 번 채점되는 일은 없게 잠근다(mediaedu와 동일).
- **노트가 그 사이 바뀌면** 기존 채점 경로가 이미 "포기 + 안내"로 처리한다. 그대로 따른다.
