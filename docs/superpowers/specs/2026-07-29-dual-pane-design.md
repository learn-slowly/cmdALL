# C. 두 폴더 나란히 보기 (듀얼 페인) — 설계

- 날짜: 2026-07-29
- 상태: 설계 승인 대기
- 상위 문서: `2026-07-25-finder-preview-direction.md`(조각 C, 순서 ①안의 세 번째)·`2026-07-03-finder-replacement-roadmap.md`(F4, "이동·복사의 무대")
- 사용자 결정 5건(2026-07-29, 채팅으로 확인):
  1. 두 칸은 **버튼 하나로 켜고 끄기**(평소엔 한 칸, 필요할 때만 두 칸)
  2. 왼쪽 사이드바(폴더 나무)는 **하나만** 두고, **클릭해서 마지막으로 손댄 칸**의 폴더를 바꾼다
  3. 한쪽에서 다른 쪽으로 파일 옮기기는 **마우스로 끌어다 놓기만**(이미 있는 드래그 기능 재사용, 화살표 버튼은 안 만듦)
  4. 파일을 눌러 크게 보면 **그 칸이 그 자리에서 리더 화면으로 바뀐다**
  5. 창이 좁아지면 **자동으로 접지 않고**, 최소 창 너비를 정해서 그 밑으로는 안 줄어들게 한다

---

## 쉬운 말 요약 (레고용)

- **이번에 할 일**: 화면 위쪽에 버튼을 하나 만들어서 누르면 오른쪽에 칸이 하나 더 생긴다. 왼쪽 칸에서 다운로드를 보고 있으면, 오른쪽 칸에 목적지 폴더를 띄워 놓고 파일을 끌어다 놓으면 바로 옮겨진다. 왼쪽 사이드바에서 폴더를 클릭하면 방금 눌렀던 칸(왼쪽이든 오른쪽이든)의 폴더가 바뀐다. 칸 안에서 파일을 누르면 그 칸이 그 파일을 읽는 화면으로 바뀐다(다만 이번엔 **읽기 전용**으로 하고, 고쳐 쓰려면 "이 창에서 제대로 열기" 버튼으로 지금처럼 한 칸 모드로 돌아가 편집하게 한다 — 아래 §5에서 이유 설명, 확인 필요).
- **이번엔 안 할 일**: 창을 두 개 띄우는 것(앱 구조상 창은 하나), 칸마다 따로 편집 가능하게 만드는 것(§5 참고, 필요하면 다음에 별도로), 자동으로 칸을 접었다 펴는 것(대신 최소 너비만 정함).
- **순서**: 이 설계 문서를 레고님이 확인 → 실행 계획서(태스크 목록) 작성 → 승인 → 태스크 하나씩 구현+검사 → 마지막 통째 확인.

## 1. 목적

지금 cmdALL은 화면에 폴더를 **하나만** 본다. 다운로드에서 파일 몇 개를 골라 프로젝트 폴더로 옮기려면 "다운로드 보기 → 옮기기 → 프로젝트 폴더로 이동 → 확인 → 다시 다운로드로" 왔다 갔다 해야 한다. 이 조각은 화면을 좌우로 갈라 양쪽에 서로 다른 폴더를 띄워, 정리 작업을 한 화면에서 끝내는 게 목적이다. 로드맵 F4("이동·복사의 무대, 파일 정리 완성형")의 실제 구현.

## 2. 실측으로 확인한 것 — "폴더 하나"라는 전제가 박혀 있는 곳

`AppState.swift`·`ContentView.swift`·`MainEditorView.swift`를 코드로 확인했다(추측 아님).

| 상태/구조 | 지금 하는 일 | 실측 위치 |
|---|---|---|
| `currentFolder` | 사이드바 트리의 뿌리 폴더(전역 1개) | `AppState.swift` |
| `selectedFolder` | 라이브러리가 보여주는 폴더(전역 1개) | 〃 |
| `mainMode`(reader/library) | 화면 전체가 리더냐 라이브러리냐(전역 1개) | 〃 |
| `tabs`/`activeTabId` | 열린 파일 탭 목록·현재 보는 탭(전역 1개) | 〃 |
| `navHistory` | 뒤로/앞으로 기록(폴더 1개 기준) | 〃 |
| `ContentView` | `NavigationSplitView { 사이드바 } detail: { MainEditorView 하나 }` — 화면 오른쪽이 통째로 한 덩어리 | `ContentView.swift:21-30` |
| 세션 저장(`SessionState`) | `currentFolder` 하나만 저장 | `AppState.swift` |
| 파일 옮기기 창 기본 경로 | `selectedFolder ?? currentFolder` 하나 | `AppState.swift:2612` |
| 검색·색인 뿌리 | `currentFolder` 하나 + 등록 폴더들 | `AppState.swift:1556-1583` |

즉 "폴더 둘을 동시에 보여주기"는 이 전역 상태들을 그대로 두 배로 만드는 게 아니라, **화면 오른쪽 영역을 쪼개는 새로운 상위 개념**을 하나 얹는 방식이라야 기존 코드(20곳 넘게 얽힌 단일 폴더 전제)를 건드리지 않고 안전하게 만들 수 있다.

## 3. 설계 방향

### 3.1 핵심 개념 — "칸(Pane)"

새 모델 `BrowsePane`(순수 구조체, 새 파일):

```
struct BrowsePane {
    var rootFolder: URL          // 이 칸이 보여주는 뿌리 폴더
    var selectedFolder: URL      // 이 칸이 지금 보여주는 폴더(뿌리 밑 어딘가)
    var layout: LibraryLayout    // list/grid — 기존 타입 재사용
    var sort: LibrarySort        // 기존 타입 재사용
    var peekFile: URL?           // 눌러서 읽고 있는 파일(있으면 리더 화면으로 표시)
}
```

- **기존 `mainMode`/`selectedFolder`/`tabs`는 손대지 않는다.** 한 칸 모드(지금 그대로)는 지금 코드 그대로 동작 — `dualPaneEnabled == false`일 때는 아무것도 안 바뀜.
- `dualPaneEnabled: Bool` 켜면 `AppState.panes: [BrowsePane]`(정확히 2개)가 생기고, 오른쪽 detail 영역이 `HStack { PaneView(0) | Divider | PaneView(1) }`으로 바뀐다.
- `focusedPaneIndex: Int`(0 또는 1) — 사이드바에서 폴더를 클릭하면 이 인덱스의 칸이 바뀐다(사용자 결정 2). 칸을 클릭하면 그 칸이 focus를 가져간다.
- 드래그 이동(사용자 결정 3)은 **F2에서 이미 만든 드롭 처리(`FileDropDelegate`·`DropGuard`·`handleFileDrop`)를 그대로 재사용** — 지금도 라이브러리 셀에 파일을 끌어다 놓으면 이동하는 기능이 있으니, 두 칸이 각자 자기 폴더를 보여주는 라이브러리일 뿐이면 드래그는 거의 공짜로 된다.

### 3.2 파일을 눌렀을 때 — 리더로 바뀌는 문제(사용자 결정 4)

여기가 이 설계에서 유일하게 위험이 남는 지점이다. 지금 "리더 화면"(글 편집·PDF·오피스 등)은 전역 `tabs` 하나에 강하게 묶여 있다 — 탭 목록·더티(수정중) 표시·닫을 때 저장 확인·되돌리기·세션 복원·Claude 패널 연동이 전부 이 탭 하나를 기준으로 짜여 있다. 칸마다 이 전체 구조를 통째로 복제하면 공사 범위가 몇 배로 커지고, 지금 잘 되는 저장·되돌리기 로직이 두 군데서 꼬일 위험이 커진다.

**그래서 이렇게 제안한다(확인 필요 — 레고님 승인 대상):**
- 칸 안에서 파일을 누르면 **읽기 전용 미리보기**로 그 칸이 바뀐다(수정 불가, `QuickLookReaderView`처럼 이미 있는 "훑어보기" 방식과 비슷한 성격 — 기존 글·PDF·이미지·오피스 렌더러를 읽기 전용으로 재사용).
- 위쪽에 **"이 창에서 제대로 열기"** 버튼을 두면, **두 칸 모드가 꺼지고** 그 파일이 지금처럼 한 칸 모드의 정식 탭으로 열린다(수정·저장·되돌리기 전부 지금 그대로 동작).
- 이렇게 하면 "두 칸 중 하나가 리더 화면으로 바뀐다"는 요청을 지키면서도, 복잡한 편집·저장 상태를 두 군데로 쪼개지 않아 위험이 크게 줄어든다.
- **대안**: 칸 안에서도 수정까지 되게 만들 수도 있다(예: 짧은 메모 정도는 고치고 싶을 때). 다만 이건 공사가 훨씬 커진다 — 필요하면 이번엔 빼고 다음 조각으로 미루는 걸 권한다.

### 3.3 최소 창 너비(사용자 결정 5)

`ContentView`에 `.frame(minWidth:)`를 사이드바+두 칸 기준으로 계산해 지정 — 두 칸이 눌려서 못 쓰게 되는 폭 밑으로는 창이 안 줄어들게 한다. 새 코드 아님, 기존 SwiftUI 표준 수정자만 사용.

### 3.4 켜고 끌 때 상태

- 두 칸 모드를 끄면 `panes` 상태는 잠깐 기억해뒀다가(세션 안에서만, 디스크 저장 안 함) 다시 켜면 마지막에 보던 폴더 두 개가 그대로 돌아온다.
- 앱을 완전히 껐다 켜는 것까지는 기억 안 한다(이번엔 안 함 — 필요하면 후속).

## 5. 이번에 하지 않을 것

- 창을 두 개 띄우는 방식(앱이 창 하나 구조라는 기존 설계 유지, 로드맵 확정 사항)
- 칸 안에서 파일 수정(§3.2 — 읽기 전용 미리보기 + "제대로 열기"로 대체, 다르게 하고 싶으면 알려달라)
- 화면 좁아질 때 자동으로 칸 접기(대신 최소 너비만 지정)
- 두 칸 모드 상태를 앱 재시작 후까지 기억하기
- A~E 다섯 조각 중 C 밖의 다른 개선
