# 교재 진도 관리 — 설계

- 날짜: 2026-08-02
- 요청: 레고 "교재 목차를 가지고 전체 진도 관리해주면 좋겠는데"
- 결정 방식: 4문항 직접 확인 후 착수(아래 표).

## 결정 사항(레고 확인 완료)

| 질문 | 결정 |
|---|---|
| "진도"의 뜻 | **전체 공부할 분량(목차) 대비 세 가지를 나란히** — ①읽음(수동 체크) ②만듦(카드·문제 생성) ③익힘(복습 성적) |
| 목차 없는 PDF | **c + b** — 기본은 쪽 단위로만 진도 표시, 원하면 장 이름·시작 쪽을 직접 입력해 목차를 만든다 |
| 화면 위치 | **독립 모드** — 툴바 모드 선택기에 "진도"(할일 화면과 같은 승격 방식, `MainMode.progress`) |
| 관리 범위 | **여러 권 목록 + 각각 진도율** — 등록한 교재 전부를 한 화면에서 |

## 이미 있는 재료(새로 모을 것 없음)

- 카드·문제 항목마다 앵커 줄에 **`src`(교재 상대경로) + `loc`(쪽/줄)** 이 이미 적힌다(§3.3, `StudyNoteParser.ParsedItem`).
- 항목마다 **복습 상태**(`due`/`ivl`/`ease`/`reps`/`lapses`)가 같은 앵커에 쌓인다.
- **목차 추출의 2/3는 이미 있다** — 마크다운은 `studyHeadingChoices`(줄 번호 포함), 오피스는 `StudySourceLoader.labeledSections`(구간 번호). 학습도우미 범위 선택에서 쓰는 그 목록이다.
- 부족한 하나: **PDF 목차**. `outlineRoot`를 쓰는 코드가 저장소에 하나도 없다(검색 0건) — 이번에 새로 만든다.

## 진실의 출처 — 교재 한 권 = 진도 노트 파일 하나

복습 상태를 노트 앵커에 남기는 기존 원칙(§3.1 "캐시는 파생, 진짜 기록은 파일")을 그대로 따른다.
**설정 JSON에 넣지 않는다** — 목차를 손으로 고치는 요구(2-b)가 있고, 옵시디언에서 그대로 보이고 백업되는 편이 낫다.

저장 위치: `<학습 폴더>/진도/<교재파일이름>.md` (학습 폴더 = `effectiveStudyFolders()`의 첫 폴더).

```markdown
---
study_progress_id: <uuid>
study_source: <percent-encoded 상대경로>     # 진도 노트 폴더 기준 (기존 study_source와 같은 규칙)
study_source_kind: pdf                      # pdf | markdown | office
study_outline_unit: page                    # page | line | section
study_total: 500                            # 총 분량(쪽 수 / 줄 수 / 구간 수)
study_updated: 2026-08-02
---

# 진도: 자격증 교재.pdf

<!-- outline no=1 start=1 end=44 read=no -->
## 1장 총론 (1~44쪽)

<!-- outline no=2 start=45 end=120 read=yes done=2026-08-02 -->
## 2장 계약 (45~120쪽)
```

- 앵커 키: `no`(1-based 순번) · `start` · `end` · `read`(yes/no) · `done`(읽음 표시 날짜, 선택).
- **미지 키는 보존**한다(기존 `StudyNoteParser.parseAnchorLine`과 같은 계약).
- 사용자가 이 파일을 직접 고쳐도 된다 — 그게 결정 2-b(직접 입력)의 기본 경로다. 앱 안에서도 "장 추가"로 같은 줄을 만든다.
- 진도 노트는 **복습 대상이 아니다**: `study_id`가 없으므로 `StudyIndex.rebuild`가 자동으로 걸러낸다(항목 0건 취급). 별도 조치 불필요.

## 목차 추출(`StudyOutlineExtractor`, 순수/신규)

| 교재 종류 | 단위 | 뽑는 방법 | 목차가 없을 때 |
|---|---|---|---|
| PDF | 쪽 | ①내장 목차(`outlineRoot`) → ②**목차 페이지 글자 파싱**(주 경로, 아래 실측) | "전체 N쪽" 한 장 + 사용자가 직접 장 추가 |
| 마크다운/텍스트 | 줄 | 기존 헤딩 목록 재사용(원본 줄 번호) | 헤딩 0개 → 전체 1구간 |
| 오피스/HWP | 구간 | 기존 `labeledSections` 재사용 | 구간 1개 → 전체 1구간 |
| 이미지 | — | 대상 아님(진도 개념 없음) | — |

- 각 장의 `end`는 **다음 장 시작 − 1**, 마지막 장은 총 분량. 목차 순회 중 시작 위치가 역행하거나 중복이면 그 항목은 버린다(깨진 목차 방어).
- 중첩 목차(1장 > 1.1절)는 **1차에서 최상위만** 쓴다. 깊이가 필요해지면 후속.
### 실측 결과(2026-08-02, 확인 완료 — 설계를 바꿈)

집에 있는 PDF 200여 개 중 대표 10개를 실제로 열어 `outlineRoot`를 확인했다.

| 파일 | 내장 목차 |
|---|---|
| **미디어교육사 교재_개정판(2025년).pdf** (562쪽, 레고님 실제 교재) | **0개** |
| 정의당 지방선거 공약자료집 (224쪽) | 0개 |
| 임금체불 최종보고서 (157쪽) | 0개 |
| 유형근2012 스캔본 (336쪽) | 0개 |
| fairclough-2003-analysing-discourse (영문 학술서) | 4개 |
| lukes-2005-power-a-radical-view (영문 학술서) | 11개 |

→ **한국 PDF에는 내장 목차가 사실상 없다.** 영문 학술서에만 있었다. 내장 목차만 믿는 설계였으면 레고님 실제 교재에서 곧바로 "전체 562쪽" 한 덩어리로 떨어졌을 것이다.

대신 그 교재의 **4~5쪽에 목차가 글자로 실재**한다(실측 발췌):

```
1.1.1. 미디어 개념과 특징 ∙ 008
1.1.2. 미디어 산업의 구조와 특성(영향력) ∙ 033
3.3.1. 미디어 리터러시 교육을 위한
수업 전문성과 교육자 전문성 ∙ 500
```

→ **목차 페이지 글자 파싱을 주 경로로 삼는다**(`StudyTOCTextParser`, 신규 순수 부품).
- 목차 페이지 판정: 앞쪽 20장 중 "제목 + 구분기호 + 쪽번호"로 끝나는 줄이 4줄 이상인 장.
- 줄바꿈된 제목(위 3.3.1 예시)은 **다음 줄에 번호가 나오면 앞줄을 제목에 이어 붙인다**.
- 쪽번호가 없는 상위 제목("1.1. 미디어 개념과 기능…")은 장으로 세지 않는다 — 쪽번호가 붙은 항목이 실제 학습 단위다(이 교재 기준 약 20장으로 딱 맞는 굵기).

### 인쇄 쪽번호 ≠ PDF 장 번호 (보정값 필요)

같은 교재에서 목차의 "74쪽"은 실제 PDF **73번째 장**, "200쪽"은 **199번째 장**이었다(제목 검색으로 실측 — 차이 −1). 표지·목차가 앞에 붙는 만큼 어긋난다. 쪽 번호가 그림으로 찍혀 있어 글자로는 안 읽히므로 자동 판독이 불가능하다.

- 앱이 **제목 몇 개를 본문에서 찾아 차이의 최빈값**을 보정값으로 제안하고,
- 사용자가 미리보기로 확인해 ±로 고칠 수 있게 한다(제안→확인→실행 원칙).
- 확정된 보정값은 진도 노트 frontmatter `study_page_offset`에 저장한다.

## 진도 3종 계산(`StudyProgressCalculator`, 순수/신규)

각 장은 `[start, end]` 구간이고 그 **분량 = end − start + 1**. 전체 분모는 `study_total`.

1. **읽음** = `read=yes`인 장들의 분량 합 ÷ 총 분량
2. **만듦** = 그 구간 안에 카드·문제가 **1개 이상** 있는 장들의 분량 합 ÷ 총 분량
3. **익힘** = Σ(장 분량 × 그 장의 익힘도) ÷ 총 분량
   - 장의 익힘도 = 익힌 항목 수 ÷ 그 장 항목 수 (항목 0개면 0)
   - **익힘 기준: `ivl ≥ 21일`** — "3주 뒤에 다시 봐도 될 만큼 익은 항목". SM-2 계열의 통상적인 young/mature 경계값이고, 앞서 정한 간격 상한 180일과도 어긋나지 않는다.

항목 → 장 매핑:
- PDF: `loc`이 `.page(n)`/`.pageRange(a,_)` → `a`가 속한 장
- 마크다운: `.line(n)` → `n`이 속한 장
- 오피스: `loc`은 항상 `.unknown`이라 **매핑 불가** → 아래 후속 조각으로 해결

**오피스 교재 처리(후속 조각 7)**: `StudyNoteWriter`가 frontmatter에 `study_range: section:3-5`(만들 때 고른 범위)를 함께 적게 하고, 그 노트의 항목들을 3~5번 구간에 통째로 귀속시킨다. 그 전까지(그리고 옛 노트는) 오피스 교재는 **읽음 체크만** 잡히고 만듦·익힘은 0으로 표시하며, 화면에 이유를 한 줄로 안내한다.

## 캐시 변경(`StudyIndex`)

교재별로 항목을 모으려면 `src`가 필요한데 지금 캐시에 없다(노트마다 파일을 다시 읽는 건 느리다).

- `study_items`에 **`src_path` 컬럼 추가** — 앵커의 상대 `src`를 **노트 폴더 기준 절대경로로 해석한 값**(`StudySourceLink.sourceURL`). 교재가 어느 폴더의 노트에서 참조되든 한 교재로 묶인다.
- `PRAGMA user_version`으로 스키마 버전을 매기고, 낮으면 **통째로 다시 만든다**. 캐시는 파생값이라 안전하다(§3.1) — 마이그레이션을 따로 쓰지 않는다.
- 신규 조회 `items(forSourcePath:)` + `distinctSourcePaths()`(등록 안 된 교재 제안용).

## 화면(`StudyProgressView`, `MainMode.progress`)

- 툴바 모드 선택기(리더/라이브러리/할일)에 **"진도"** 추가. 할일 모드 승격 때와 같은 방식.
- 왼쪽: **등록 교재 목록** — 이름 + 3종 진도 막대(작게). 아래에 "카드를 만든 적 있는데 등록 안 된 교재" 제안 목록(원클릭 등록).
- 오른쪽: 선택한 교재의 **전체 막대 3줄**(읽음/만듦/익힘, %와 분량 함께) + **목차 표**
  - 장 제목 | 범위(쪽/줄/구간) | 카드·문제 개수 | 익힘 % | 읽음 체크박스
- 버튼: `교재 추가…`(파일 선택 → 목차 미리보기 → 저장 확인) · `장 추가…`(제목+시작 위치 직접 입력) · `목차 다시 읽기` · `노트 열기`.
- **파일 변경은 제안→확인→실행**: 진도 노트 생성·갱신은 사용자가 버튼을 누른 결과로만 일어난다. 읽음 체크 한 번 = 그 앵커 줄 하나만 치환 + `.bak` 백업 1부(채점 쓰기와 동일한 어법).

## 구현 순서(조각)

각 조각 끝에 `swift test` 전체 통과 확인(Phase 게이트).

1. `StudyOutline` 모델 + `StudyOutlineExtractor`(PDF/마크다운/오피스 + 폴백) — PDF 목차 실물 확인 포함
2. `StudyProgressNote`(순수: 진도 노트 만들기/읽기/앵커 치환)
3. `StudyIndex` 스키마 v2(`src_path`) + `items(forSourcePath:)` + `distinctSourcePaths()`
4. `StudyProgressCalculator`(3종 비율)
5. `AppState+StudyProgress`(등록·해제·읽음 체크·장 추가 배선)
6. `StudyProgressView` + `MainMode.progress` + 툴바
7. (후속) `study_range` frontmatter — 오피스 교재 자동 진도

## 이번에 하지 않은 것

- 진도에 맞춘 **자동 학습 계획**(하루 몇 쪽·시험일 역산) 및 알림.
- 중첩 목차(절 단위) 표시.
- 진도 **기록의 시간 추이**(그래프·주간 리포트).
- 교재 여러 권 통합 대시보드(권별 목록까지만).
- 앞서 정리한 다듬기 항목 A~D(복습 단축키·만들기 취소 등) — 별건.
