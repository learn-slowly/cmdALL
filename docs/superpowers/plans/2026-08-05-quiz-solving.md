# 문제 풀기 화면 — 구현 계획

- 날짜: 2026-08-05
- 설계 문서: `docs/superpowers/specs/2026-08-05-quiz-solving-design.md`
- 요청: 레고 "학습도우미 관련해서 mediaedu-quiz 확인해서 최대한 비슷하게 구현해봐"
- 상태: **Q0·Q2·Q3·Q4·Q5 완료(2026-08-05, v0.9.432 배포)**. Q1만 미룸(앱이 만든 학습 노트가 0개라 풀 대상이 없다).

## In scope / Out of scope

**In scope** — 만든 문제를 앱 안에서 **눌러서 푸는** 화면 한 벌.
문제집 고르기 · 즉시 채점(색·잠금) · 진행 통계 · 형식 탭 · 해설 접기 · 교재 원본 열기 ·
그 문제로 물어보기 · 틀린 것만 다시 · 이번 판 다시 풀기 · 맞음/틀림을 복습 기록에 반영.

**Out of scope(이번에 하지 않을 것)**
1. 웹 배포·HTML 생성 (cmdALL은 앱이다)
2. 비밀번호·접속 열쇠 관리 (mediaedu 고유 사정)
3. 문제 만드는 프롬프트·형식 규칙 손대기 (6형식 100문항은 그 시험 전용 규격)
4. **찍기 방지 검사**(보기 길이·정답 쏠림) — 만들 때 붙는 기능이라 분리, 2단계로 제안
5. 정답 번호 자동 재배치
6. 풀이 기록의 앱 재시작 후 복원(화면 표시 한정 — 복습 기록은 노트에 남으므로 손실 없음)
7. 통계·그래프·연속 학습일 (기존 학습도우미 Out of scope 2항 그대로)

## 조각 (각 조각 끝에 `swift test` 전량 통과 + 커밋)

### Q0 — 이미 있는 문제집 가져오기 (레고 요청, 2026-08-05 "저 사이트에 있는 문제 그대로 갈 순 없니?")

**실측(2026-08-05)** — 볼트 `…/12003_미디어교육사/100제/`에 문제집 md **50개**가 있고,
`quiz_md.parse_md`로 훑으니 **50개 전부 100문항 온전 · 총 5,000문항 · 교재 쪽 링크 누락 0건**.
교재 PDF(`미디어교육사 교재_개정판(2025년).pdf`)도 같은 폴더에 있어 원본 열기가 바로 이어진다.

새로 만들 필요가 없다. **가져오면 곧바로 5,000문항이 풀 거리가 된다** — 풀기 화면보다 먼저 한다.

원본 형식(그대로 두고 읽기만 한다):

```markdown
## A. 옳은 것 고르기 (1~18)

**1.** 커뮤니케이션에 대한 설명으로 옳은 것은?
① 반드시 사람과 사람 사이에서만 일어난다.
② 발화자와 수신자 사이에 의미를 주고받는 것이다.
…

# 정답 · 해설

**1. ②** 커뮤니케이션 = 의미를 주고받는 것. [[…교재….pdf#page=9|📖 p.009]]
```

| 파일 | 상태 |
|---|---|
| `Sources/Services/QuizImportParser.swift` | **완료(2026-08-05, `0fc79a1`)**. 위 형식 → `[StudyQuestion]`. 섹션 머리글=`type`, `#page=NNN`→`loc`, 한 줄에 붙은 보기·해설도 나눈다 |
| `Sources/Services/StudyNoteWriter.swift` | **완료**. 근거 인용이 없을 때 `> 근거:` 줄 생략. 기존 동작 불변 |
| `Tests/CmdMDTests/QuizImportParserTests.swift` | **완료**. 16개 통과 · 실제 볼트 5,000문항 전부 파싱 확인 |
| `Sources/Services/QuizRecordNote.swift` | **남음**. 기록장 읽기/쓰기(앵커 `n=` 방식, 아래 변경 참고) |
| `Sources/App/AppState+QuizImport.swift` | **남음**. 문제집 고르기 → 몇 문항 읽혔는지 보여주기 → **확인 후** 기록장 생성 |

**⚠️ 방향 변경(레고 지적, 2026-08-05) — 문제집을 복제하지 않는다.**
원래는 원본을 학습 노트로 **새로 써서** 옮길 계획이었으나(5,000문항 한 벌 더), 같은 날 겪은
"정답이 두 곳에 적혀 74곳 어긋남" 사고와 똑같은 병을 만드는 짓이다. 대신 **교재 진도 관리와
같은 방식**으로 원본은 그대로 두고 **기록장**(`<학습 폴더>/문제집기록/<원본이름>.md`)만 만든다.
문제 본문은 화면에 띄울 때마다 원본에서 읽는다. 상세는 설계 문서 §설계 변경.

### Q1 — 뒤로 미룸 (앱이 만든 문제 노트를 읽는 파서)

레고 "다 지우고, 저 웹사이트를 구현하는 것에 집중하자"(2026-08-05). 학습도우미가 만든
문제 노트 50문항·카드 노트 2개를 전부 지워(볼트 커밋 `c1eff4f`·`1a7bb28`) **앱이 만든
학습 노트가 볼트에 0개**가 됐다. 지금 풀 것은 100제 5,000문항뿐이므로 이 조각은 뒤로 미룬다.

풀 수 있는 문제집이 두 종류라 입구가 둘인 것은 그대로다 — 나중에 학습도우미로 문제를
새로 만들면 그때 필요해진다.

| 문제집 | 본문이 있는 곳 | 읽는 것 | 복습 기록 |
|---|---|---|---|
| 밖에서 만든 것(100제 등) | 원본 문제집 md | **Q0** `QuizImportParser`(완료) | 기록장(신규) |
| 앱이 만든 것(학습도우미) | 학습 노트 항목 `body` | Q1 `StudyQuizParser`(미룸) | 같은 노트의 앵커(기존) |

화면·채점·필터는 둘이 완전히 같은 것을 쓴다 — **읽어 들이는 입구만 둘**이다. 그래서 지금
Q0만으로 화면을 끝까지 만들 수 있고, 나중에 Q1을 더해도 화면은 손대지 않는다.

미뤄 둔 실측 기록(그때 지운 50문항 노트 기준): `mcq` 40 · `OX` 6 · `단답` 4 —
**눌러서 풀 수 있는 문항 92%**. OX 갈래가 12%였으므로 화면에는 O·X 두 버튼 갈래가 필요하고,
보기는 4개였으므로 5지선다로 고정하지 않는다. 이 두 결론은 Q0 경로에도 그대로 적용된다.

### Q2 — 기록장 (원본은 손대지 않는다)

| 파일 | 변경 |
|---|---|
| `Sources/Services/QuizRecordNote.swift` | **신규**. 기록장 읽기/쓰기(순수). `<!-- quiz item=… n=1 due=… ivl=… -->` 앵커. 원본에서 읽은 문항 수로 기록장을 만들고, 채점 결과로 앵커 한 줄만 치환 |
| `Sources/App/AppState+StudyQuiz.swift` | **신규**. 문제집 목록·열기·기록장 만들기(확인 후)·채점 저장(백업 1부 + 쓰기 직전 재확인, 기존 규약 그대로) |
| `Tests/CmdMDTests/QuizRecordNoteTests.swift` | **신규**. 앵커 왕복 · 미지 키 보존 · 문항 수가 달라졌을 때 번호로 다시 맞추기 · 사라진 번호 기록 유지 |

문제집 목록은 **폴더를 훑어** 만든다(`QuizImportParser`로 문항 수를 세고, 기록장이 있으면
오늘 풀 몫도 함께). `StudyIndex`(복습 캐시)를 넓히는 것은 화면이 자리 잡은 뒤로 미룬다 —
5,000문항을 캐시에 넣기 전에 화면에서 실제로 쓸모가 있는지 먼저 본다.

## 위험과 대비

| 위험 | 대비 |
|---|---|
| AI가 만든 정답 표기가 제각각 | 파서 5단계 + 실패 시 기존 "스스로 채점" 방식으로 대체(화면이 비지 않음) |
| 한 문제가 두 번 채점됨 | 답을 고르는 즉시 잠금(mediaedu와 동일) |
| 채점 도중 노트가 바뀜 | 기존 채점 경로의 "포기 + 안내" 그대로 |
| 복습 기록이 지워질까 봐 | "기록 초기화" 대신 **"이번 판 다시 풀기"**(화면 표시만 지움) |
