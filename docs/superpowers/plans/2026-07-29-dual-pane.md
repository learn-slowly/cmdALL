## 쉬운 말 요약 (레고용)

- **이번에 만드는 것**: 화면 위 버튼 하나로 오른쪽 화면을 두 칸으로 가른다. 왼쪽 사이드바에서 폴더를 누르면 마지막으로 눌렀던 칸이 그 폴더로 바뀐다. 파일은 끌어다 놓으면 옮겨진다(F2에서 이미 만든 기능 재사용). 칸 안에서 파일을 누르면 그 칸이 읽기 전용으로 그 파일을 보여주고, "이 창에서 제대로 열기"를 누르면 두 칸이 접히고 지금처럼 수정 가능한 한 칸 화면으로 열린다.
- **이번엔 안 하는 것**: 두 칸 각각에서 여러 개 파일을 동시에 골라 옮기는 건 **포커스 있는 칸에서만** 된다(아래 추가 결정 참고) — 반대쪽 칸은 보여주기+드롭 받기 전용. 칸 안 수정. 재시작 후 두 칸 상태 기억.
- **순서**: 태스크 1~7을 하나씩 만들고, 태스크마다 자동 검사(swift test) 통과 확인 후 커밋. 마지막에 레고님이 실제로 눌러보고 확인.

### 설계 문서에 없던 추가 결정 1건(구현 중 필요해서 지금 정함 — 확인 필요)

두 칸을 각각 독립적으로 다중 선택하게 만들려면 지금 앱 전체가 쓰는 "선택된 파일 목록"(`fileSelection`)·"화면에 보이는 순서"(`libraryOrderedURLs`) 같은 상태를 칸마다 복제해야 한다. 이건 F1b가 짜놓은 배치 이동·⌘A·⇧범위선택 로직 전체를 두 벌로 만드는 셈이라 이번 조각의 범위를 크게 넘는다.

**그래서**: 다중 선택·⌘C/⌘V·배치 메뉴는 지금처럼 **포커스 있는 칸에서만** 동작한다(기존 전역 상태 그대로 재사용). 포커스 없는 칸(반대쪽)은 파일을 보여주고 드롭을 받는 것만 된다 — 거기서 파일을 골라 선택하려면 먼저 그 칸을 클릭해 포커스를 옮겨야 한다. 한 개짜리 드래그(포커스 없는 칸에서 파일 하나를 바로 끌어다 놓는 것)는 F2 드래그가 이미 클릭/선택과 무관하게 동작하므로 **그대로 된다**(선택 여부와 드래그는 별개 경로).

---

**Goal:** 화면 오른쪽을 두 칸으로 나눠, 왼쪽 칸과 오른쪽 칸에 각자 다른 폴더를 띄우고 그 사이에서 드래그로 파일을 옮길 수 있게 한다. 기존 한 칸 모드(지금 동작)는 손대지 않는다.

**Architecture:** 새 상태 `AppState.dualPaneEnabled`/`panes: [BrowsePane]`/`focusedPaneIndex`를 추가하고, `ContentView`의 detail 영역이 이 플래그로 `MainEditorView()`(기존) ↔ `DualPaneView()`(신규)를 분기한다. 칸 하나(`PaneView`)는 기존 `LibraryListing`(순수 열거 함수)·`LibrarySorting`(순수 정렬 함수)·F2 드롭 컴포넌트(`FileDropDelegate`)를 그대로 재사용하되, 전역 `selectedFolder` 대신 그 칸 자신의 `BrowsePane.selectedFolder`를 본다. 파일 클릭 시 읽기 전용 렌더러(기존 뷰를 `isEditable: false`류 파라미터로 감싸거나 신규 `PaneReaderView`가 조립)로 전환한다.

**Tech Stack:** Swift 5.9+ / SwiftUI, XCTest. 새 패키지 의존성 없음.

## Global Constraints

- 새 패키지 의존성 0.
- macOS 14+ / Swift 5.9+.
- 코드 주석·커밋 메시지·UI 문구는 **한국어**.
- 글에서 '박다/박는다/박았다' 표현은 쓰지 않는다.
- **원본 파일 불변.** 이동은 기존 `FileOperations.move`/`performBatchMove`(휴지통 이동만, 되돌리기 가능)를 그대로 통과시킨다 — 새 이동 로직을 만들지 않는다.
- 신규 기능은 **별도 파일**로 분리한다.
- **한 칸 모드는 절대 건드리지 않는다** — `dualPaneEnabled == false`일 때 기존 `mainMode`/`tabs`/`selectedFolder`/`navHistory` 경로는 지금과 100% 동일하게 동작해야 한다. 각 태스크 끝에 이 회귀가 없는지 특히 확인한다.
- 다중 선택·⌘C/⌘V/배치 메뉴는 **포커스 있는 칸에서만**(위 "추가 결정" 참고) — `fileSelection`/`libraryOrderedURLs`는 칸마다 복제하지 않는다.
- 칸 안 파일 클릭 = 읽기 전용 미리보기만(수정 불가). 수정하려면 "이 창에서 제대로 열기" → 두 칸 모드 해제 + 기존 탭으로 열기.
- 각 태스크는 `swift test` 전체 통과로 끝난다. **기준선 931개**(2026-07-29, 최근 커밋 기준). 기존 테스트를 깨뜨리지 않는다.
- 테스트는 XCTest, `@testable import CmdMD`. `AppState`를 쓰는 테스트는 반드시 `AppState(dataDirectory: TempDataDirectory.make())`로 격리한다.

  4. 칸 안 파일 클릭 = 읽기 전용, "제대로 열기"로 한 칸 모드 전환
  5. 창 줄여도 두 칸이 안 눌림
  6. 한 칸 모드(토글 끈 상태)에서 기존 기능 전부 평소와 동일(회귀 없음)
